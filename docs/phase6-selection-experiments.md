# Phase 6 selection experiments

Historical design evidence for the common guard/capture path. Current production behavior and validation are recorded in the Phase 6 plan; descriptions of earlier probes below refer to their original candidates. The [Phase 6 plan](runtime-evolution-plan.md#phase-6-support-promise-valued-path-segments) selects ordinary placement gates, versioned external metadata and the existing native reservation kernel with immediate completion of finished reads. The superseded selection-dependency prototype and its default-suite tests have been removed. That cleanup does not gate the [independent recovery correction](runtime-evolution-plan.md#repair-and-call-recovery-fix), which is implemented separately.

## Managed-only reservation removal

The external review's managed-only reservation removal is useful existing evidence, not another untested hypothesis. Its saved run reports 5,468 passing tests with one Promise-shape assertion failure, 9,600 external sequence programs and all four conflict-matrix partitions. Re-running its isolated external-path suite against the saved patch reproduces 199 passes and that one `failure instanceof Promise` assertion. A separate in-memory test substitution removes only that assertion and passes all 200 tests, including the remaining effect/publication assertions. Reconcile the assertion with the operation's completion contract when landing the simplification; the production source is not changed by these probes. The per-selection predecessor proposal is rejected by the quadratic-history result below. Follow-up production probes narrow the benefit: valid managed assignment/deletion, a managed call, Array push and a leaf repair already progress while a native sibling is pending. The remaining reservation holds the old computed failure prefix or a tree-proven invalid mixed managed scope. A computed crossing into P.a.api waits behind P.b.svc and also holds disjoint P.c.other; an invalid scope at P.a waits for its native child before publishing PropertyValidation. Remove those holds with local failure/B16, not in a separate managed-reservation slice. Preserve reservations still needed for native-prefix metadata, query/repair and fixed entry ordering until their replacements land.

## Withdrawn mixed-entry progress claim

The later review withdraws its probe E as a progress defect. A computed mixed entry at P can repair descendant api metadata, and its managed gate also orders a later api call's namespace capture. That call may therefore legitimately wait for the entry. This history does not justify narrowing the entry's fixed coverage or adding another dependency representation. Managed gates, metadata versions and native reservations can constrain the same operation while protecting different state and last-use boundaries; apparent overlap alone does not prove redundant machinery. Keep the Phase 6 public-operation checkpoint for actual handoff, lifetime and work bounds.

## Accepted read-completion simplification

Reads remove no predecessor frontier entries, so a finished read can complete immediately after its own required host access and effect work finish; any remaining work uses already captured state. Later conflicting work retains each earlier dependency directly or through a replacing mutation; mutation/exclusive completion still waits. The candidate scratch copy was checked against all 43 production source files and differed only in ExternalEffect's retained mode and read-completion branch. An independent 32-case check covered global and entry views, waiters issued before and after release, original and replaced predecessors, overlapping ancestors/descendants, sibling progress and entry completion. The unmodified kernel unnecessarily held the unrelated sibling; the candidate released it while preserving true conflicts. These checks establish the local reservation rule, not full Phase 6 path/metadata integration. Port those cases to the production suites when implementing the rule.

## Superseded selection-dependency prototype

Capturing predecessors separately per unresolved selection creates quadratic history: 1,024 selections retained 523,776 links even when all later selected no external work.

The grouped/indexed/shared-wait follow-up is not part of the selected architecture. Phase 6 removed its five files and default-suite coverage before production implementation, with no maintained alternative kernel or benchmark suite left behind.

## Confirmed crossed-identity registration gap

The late-registration probe was rerun against production: registration before issuance rejects a root, intermediate identity or receiver; registration during an argument wait rejects only the receiver, while crossing either earlier identity still permits invocation. This is tracked as an [open Phase 5 finding](phase5-review.md#open-finding-crossed-identity-late-registration), with its affected obligations reopened. The focused runtime fix can land independently of Phase 6: retain and recheck relevant noncanonical native path identities without replaying getters, then release them at last authority use. Phase 6 must preserve that correction across its registration cutover and add pending-key coverage. This historical gap is now corrected by retained noncanonical route checks and the production binding-diagnostics tests.

## Failed-repair cutover and candidate reservations

Production probes confirm that known-forbidden computed repair and repair-and-call can poison a healthy managed static prefix or static native owner, preventing later static recovery/access. The inspected review scratch copy differs from production only in PathOperation: it removes scope-depth narrowing and suppresses non-repair managed-node reservations without a native prefix. It still loses repair intent on route failure. That copy poisons the selected healthy resource placement instead; an explicit computed bang at the resource, repair and repair-and-call still wait for that resource's pending native call. This is a negative witness, not an accepted implementation. [Failed-repair preservation](data-limitations.md#repair-and-call-preflight) and removal of candidate reservations therefore belong in the local-failure/B16 cutover.

Separate production controls hold api!.slow() pending, then issue invalid repair or repair-and-call through its computed registered child. Rejecting slow makes both return the exact original InvocationFailed, with no child call or fatal. Preserve that genuine native-prefix dependency using read ordering until versions replace it; rejected repair publishes no failure/reset and reserves neither mutation authority nor the computed candidate. A pending candidate child is a different history from a pending statically selected owner.

The next production probes distinguish terminal-alias/unregistered-receiver repair-and-call from structural rejection: repair commits, then a new ExternalLocationConflict replaces the old guard, with zero host calls. A prefix-only read at a static owner also completes while either the computed child or a sibling's native call remains pending, confirming the narrow interim ordering option. A further pending-baseline control exposed the [original repair/call availability defect](phase5-review.md#corrected-finding-repair-and-call-skipped-pending-recovery-availability); ready and ordinary pending-call controls succeed, while repair-and-call originally reached dispatch with an unadmitted Promise. These are confirmed observations, not implementation acceptance.

## Confirmed ready computed-key sibling blocking

The supplied wrapper-hold probe and independent fresh-Chain controls reproduce synchronous sibling lookup for a static target versus a pending lookup for the equivalent ready computed target while its managed method remains pending. Both final sibling values are correct after release. This is the [open Phase 5 B16 finding](phase5-review.md#open-finding-ready-computed-key-sibling-blocking). The follow-up pending-intermediate probe shows why wrapper removal cannot preserve the old failure policy: computed P[a].ext.x = 2 can later poison all of P, so the wrapper must keep a later sibling write behind it. Static traversal leaves that sibling healthy. Land the ordinary direct walk and removal of the obsolete managed-prefix reservation together with the ready-key local-failure cutover, and retain both success/progress and failure/ordering regressions. No Promise-key or metadata-version implementation is needed, but the failure-policy dependency is real. The production local-failure and Promise-path tests now retain these progress and failure cases.

## Repair-and-call dispatch boundary

The production probe confirms that unsupported Array names and constructor commit repair and publish new MissingFunction/NotAFunction poison; valid push proceeds on the restored Array. The selected plan keeps this ordinary post-repair dispatch behavior. Structural route, mutation scope and readonly validation alone precede clearing. Add public acceptance across ready and deferred selection; no duplicate early dispatch path is needed.

## Ordering witnesses

These histories motivated the selected architecture and remain regression requirements for its implementation. Current behavior and mechanisms belong to [ordered metadata](data-limitations.md#ordered-external-metadata) and [publication handoff](external-context-ordering.md#metadata-publication-handoff); production coverage lives in the path, external metadata and generated-sequence suites.

Versioned metadata remains selected. If P.a owns E, a query through unresolved P[k] is issued, P.a is repaired, and k later selects a, the query must still return E. Releasing a prefix read reservation before key selection cannot preserve that result by itself. It would require retained versions, a snapshot of possible unselected branches, or holding later writers until the key resolves. The latter two relax the accepted work/progress contracts and are not selected. Removing cross-context conflict publication simplifies the metadata writers; it does not remove the need to capture earlier state.

Retain public-operation witnesses for these cases, using all-ready, synchronous custom, and deferred keys:

- Under an external api, issue repair R1 through api[k] with k pending, capture an intervening query, then issue covering repair R2 at api. With R2's own prerequisites ready, R2 and a post-reset query complete without k. The earlier query and R1 retain their required completion; late R1 success or failure cannot repopulate R2's reset. Repeat with a pending mutating-entry metadata publication covered by R2, while retaining its native effects/coverage. Add strict-ancestor own poison and managed restoration/gate controls where R2 must still wait. The next witness supplies the explicit descendant-reset dependency.
- Give api its own poison and register child api.x. Issue R1 through api[k], then R2 through api.x, then getErrors(api.x). If k selects registered x, R1 is blocked by api's own poison and the later repair/query remain blocked. If k selects an unregistered suffix, its selected metadata scope is api itself: R1 clears api and the later repair/query succeed. R2 cannot decide before k in this history. Use the ordinary static/ready paths as the reference, then synchronous/deferred keys. Separately use a known healthy api own state with no managed or strict-ancestor prerequisites: R2's covered reset and post-reset query can complete without k, while earlier captures retain R1's required outcome. Unknown selection does not by itself prove that api's own state is unchanged.
- Keep a mutating entry E at api open, issue an outside native mutation N at api.x during the callback, and capture an outside query Q at api.x after N. N's native work waits for E, but its metadata successor is established at issuance. Close E, then let N fail: both Q and a later getErrors(api.x) must include N's Error. Entry publication cannot erase that successor. Keep unrelated nested work pending separately to verify metadata handoff does not complete native coverage.
- Issue repair R through unresolved P[k], then native mutation N2 at P.b.api, then query Q there. Resolve k to b, complete valid repair and let N2 fail. Q must include N2's Error, not just R's cleared subtree. Repeat with a different selected branch, failed repair prerequisites and repair waiting for managed restoration. After capturing Q, issue a later valid ancestor reset and complete its own prerequisites: Q keeps its earlier required outcome, while post-reset queries stay clear after the old chained publication fails. Include a case where the later ancestor reset can commit while Q still waits at its managed gate; Q must retain its earlier view when the gate opens. Cover ready, synchronous and deferred prerequisite/native-outcome delivery as well as key delivery.
- An earlier native mutation at P.api remains pending. Issue an ordinary managed mutation through an unresolved key under managed P, then later native accesses at P.api and its independent registered sibling P.other, followed by an ancestor metadata query or mixed entry. Resolve the key to a managed non-resource child whose selected transition remains pending. Publish the normal narrow managed protection and allow P.other to proceed without waiting for that child or the unrelated earlier P.api mutation. Same-scope and ancestor work must still retain the earlier P.api dependency, including if broad frontier membership was replaced. Earlier captures preserve their values and identity decisions. Repeat inside an entered view.
- Issue a contextual query through an unresolved managed key before a later native failure or repair in the eventual target subtree. Its collected metadata excludes the later failure and preserves an earlier Error across later repair. Repeat with a selected managed sibling that contains no registered descendants: unrelated pending native work cannot become a result prerequisite. Capture only the selected metadata, without a candidate walk or native property access. Repeat after entry callback closure while a contained native sibling remains pending: metadata publication exposes the narrow pending branch, while the entry's native reservation remains active.
- Issue repair through an unresolved key under managed P, then select a managed group containing registered descendants. Hold an earlier native child mutation in that group pending. Install the selected branch transition before exposing the broader metadata view so unrelated branches proceed. Once valid selection and managed restoration/preflight finish, reset the selected metadata without waiting for that child; later independent native siblings inside the group and metadata queries proceed, while actual same-scope/ancestor native conflicts still wait. Failed repair must preserve existing managed recovery and external metadata, including a still-pending earlier failure. Preserve earlier query results and later/unrelated poison. Repeat inside an entry whose callback closes before selection/publication completes: the published view carries the remaining narrow transition, while native coverage keeps its own completion. Include a no-metadata managed sibling, direct computed canonical repair and an off-path authority failure.
- Under a statically selected external owner, let an input key resolve to a forbidden registered descendant while an unrelated child mutation remains pending. The observation uses immutable static-prefix authority and captured own poison after its required predecessors; unrelated child work neither replaces the local failure nor remains its prerequisite. Later independent child work must progress once selection is decided, while ancestor work retains its real predecessors. Invalid mutation instead preserves ordering and poison publication at the selected external owner.

Record what each operation captures at issuance, which dependencies remain after selection and what publishes or releases them. Hold irrelevant predecessors and selected work pending independently in progress tests. When a native observation's unresolved suffix becomes forbidden, finish its required prefix-metadata consumption and release its read reservation under the ordinary immediate-completion rule. Assert that existing and future waiters retain real predecessor conflicts, while unrelated siblings proceed. Replacing mutations keep the dependencies they subsumed. Metadata publication and entry closure retain their own work; read release neither discards that work nor makes live-state reads safe before their required predecessors.
