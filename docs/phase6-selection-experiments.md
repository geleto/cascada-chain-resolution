# Phase 6 selection experiments

Retained evidence for the common guard/capture path. The [Phase 6 plan](runtime-evolution-plan.md#phase-6-support-promise-valued-path-segments) selects ordinary placement gates, versioned external metadata and the existing native reservation kernel with immediate completion of finished reads. The unused selection-dependency prototype is superseded; remove its files and default-suite tests before the broader path/metadata implementation. That cleanup does not gate the [independent recovery correction](runtime-evolution-plan.md#repair-and-call-recovery-fix), which is implemented separately.

## Managed-only reservation removal

The external review's managed-only reservation removal is useful existing evidence, not another untested hypothesis. Its saved run reports 5,468 passing tests with one Promise-shape assertion failure, 9,600 external sequence programs and all four conflict-matrix partitions. Re-running its isolated external-path suite against the saved patch reproduces 199 passes and that one `failure instanceof Promise` assertion. A separate in-memory test substitution removes only that assertion and passes all 200 tests, including the remaining effect/publication assertions. Reconcile the assertion with the operation's completion contract when landing the simplification; the production source is not changed by these probes. The per-selection predecessor proposal is rejected by the quadratic-history result below. Follow-up production probes narrow the benefit: valid managed assignment/deletion, a managed call, Array push and a leaf repair already progress while a native sibling is pending. The remaining reservation holds the old computed failure prefix or a tree-proven invalid mixed managed scope. A computed crossing into P.a.api waits behind P.b.svc and also holds disjoint P.c.other; an invalid scope at P.a waits for its native child before publishing PropertyValidation. Remove those holds with local failure/B16, not in a separate managed-reservation slice. Preserve reservations still needed for native-prefix metadata, query/repair and fixed entry ordering until their replacements land.

## Withdrawn mixed-entry progress claim

The later review withdraws its probe E as a progress defect. A computed mixed entry at P can repair descendant api metadata, and its managed gate also orders a later api call's namespace capture. That call may therefore legitimately wait for the entry. This history does not justify narrowing the entry's fixed coverage or adding another dependency representation. Managed gates, metadata versions and native reservations can constrain the same operation while protecting different state and last-use boundaries; apparent overlap alone does not prove redundant machinery. Keep the Phase 6 public-operation checkpoint for actual handoff, lifetime and work bounds.

## Accepted read-completion simplification

Reads remove no predecessor frontier entries, so a finished read can complete immediately after its own required host access and effect work finish; any remaining work uses already captured state. Later conflicting work retains each earlier dependency directly or through a replacing mutation; mutation/exclusive completion still waits. The candidate scratch copy was checked against all 43 production source files and differed only in ExternalEffect's retained mode and read-completion branch. An independent 32-case check covered global and entry views, waiters issued before and after release, original and replaced predecessors, overlapping ancestors/descendants, sibling progress and entry completion. The unmodified kernel unnecessarily held the unrelated sibling; the candidate released it while preserving true conflicts. These checks establish the local reservation rule, not full Phase 6 path/metadata integration. Port those cases to the production suites when implementing the rule.

## Superseded selection-dependency prototype

Capturing predecessors separately per unresolved selection creates quadratic history: 1,024 selections retained 523,776 links even when all later selected no external work.

The grouped/indexed/shared-wait follow-up is not part of the selected architecture. [Phase 6 cleanup](runtime-evolution-plan.md#0-remove-superseded-prototype-artifacts) removes its five files and default-suite coverage before production implementation begins; removal remains planned work, with no maintained alternative kernel or benchmark suite left behind.

## Confirmed crossed-identity registration gap

The late-registration probe was rerun against production: registration before issuance rejects a root, intermediate identity or receiver; registration during an argument wait rejects only the receiver, while crossing either earlier identity still permits invocation. This is tracked as an [open Phase 5 finding](phase5-review.md#open-finding-crossed-identity-late-registration), with its affected obligations reopened. The focused runtime fix can land independently of Phase 6: retain and recheck relevant noncanonical native path identities without replaying getters, then release them at last authority use. Phase 6 must preserve that correction across its registration cutover and add pending-key coverage. The fix and validation remain pending; this is a confirmed defect, not a passing acceptance test.

## Failed-repair cutover and candidate reservations

Production probes confirm that known-forbidden computed repair and repair-and-call can poison a healthy managed static prefix or static native owner, preventing later static recovery/access. The inspected review scratch copy differs from production only in PathOperation: it removes scope-depth narrowing and suppresses non-repair managed-node reservations without a native prefix. It still loses repair intent on route failure. That copy poisons the selected healthy resource placement instead; an explicit computed bang at the resource, repair and repair-and-call still wait for that resource's pending native call. This is a negative witness, not an accepted implementation. [Failed-repair preservation](runtime-evolution-plan.md#failed-repair-during-the-ready-path-cutover) and removal of candidate reservations therefore belong in the local-failure/B16 cutover.

Separate production controls hold api!.slow() pending, then issue invalid repair or repair-and-call through its computed registered child. Rejecting slow makes both return the exact original InvocationFailed, with no child call or fatal. Preserve that genuine native-prefix dependency using read ordering until versions replace it; rejected repair publishes no failure/reset and reserves neither mutation authority nor the computed candidate. A pending candidate child is a different history from a pending statically selected owner.

The next production probes distinguish terminal-alias/unregistered-receiver repair-and-call from structural rejection: repair commits, then a new ExternalLocationConflict replaces the old guard, with zero host calls. A prefix-only read at a static owner also completes while either the computed child or a sibling's native call remains pending, confirming the narrow interim ordering option. A further pending-baseline control exposed the [original repair/call availability defect](phase5-review.md#corrected-finding-repair-and-call-skipped-pending-recovery-availability); ready and ordinary pending-call controls succeed, while repair-and-call originally reached dispatch with an unadmitted Promise. These are confirmed observations, not implementation acceptance.

## Confirmed ready computed-key sibling blocking

The supplied wrapper-hold probe and independent fresh-Chain controls reproduce synchronous sibling lookup for a static target versus a pending lookup for the equivalent ready computed target while its managed method remains pending. Both final sibling values are correct after release. This is the [open Phase 5 B16 finding](phase5-review.md#open-finding-ready-computed-key-sibling-blocking). The follow-up pending-intermediate probe shows why wrapper removal cannot preserve the old failure policy: computed P[a].ext.x = 2 can later poison all of P, so the wrapper must keep a later sibling write behind it. Static traversal leaves that sibling healthy. Land the ordinary direct walk and removal of the obsolete managed-prefix reservation together with the ready-key local-failure cutover, and retain both success/progress and failure/ordering regressions. No Promise-key or metadata-version implementation is needed, but the failure-policy dependency is real. Fix and validation remain pending.

## Repair-and-call dispatch boundary

The production probe confirms that unsupported Array names and constructor commit repair and publish new MissingFunction/NotAFunction poison; valid push proceeds on the restored Array. The selected plan keeps this ordinary post-repair dispatch behavior. Structural route, mutation scope and readonly validation alone precede clearing. Add public acceptance across ready and deferred selection; no duplicate early dispatch path is needed.
