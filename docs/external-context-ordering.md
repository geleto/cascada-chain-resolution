# External Context Ordering Architecture

The developer-facing contract is [data-limitations.md](data-limitations.md). This document specifies the external-tree architecture implemented and verified by [Phase 9F-A](first-principles-conformance-plan.md#phase-9f-a-scope-coordination-and-managed-rollback).

## Model

Managed state uses leases, sharing, COW, and placement versions. External state retains exact native identities; its access reservations and poison live in the external mutation tree, never in native properties. Observation-only external identities remain unlocked under their read-only host contract.

A mutable external subtree can contain nested registered scopes. `apis.config!.init()` and `apis.db!.addUser(1)` may overlap, while `apis!.reset()` excludes both subtrees when `apis` is external. Each mutation may change only state within its selected external scope. Parent-owned native methods may change descendant state but preserve every registered identity and location. Hidden writable overlap between supposedly independent siblings violates the host contract.

A managed mutation scope cannot cover canonical registered mutable external locations. Reject that scope before mutation and poison its selected managed root, preserving its value for repair. An inert external alias at another location does not forbid controlled managed writes, but grants no external observation or mutation authority. Native managed receiver preparation independently rejects registered mutable identities in the complete receiver. Observation-only external references remain permissible opaque leaves. Entry reserves access, may select a mixed branch, and grants no mutation authority. Its contained operations independently obey these scope restrictions.

Two scopes overlap when one is an ancestor of the other or they are equal. Ordinary external operations conflict exactly when their scopes overlap and at least one mutates. Observations can run concurrently; disjoint sibling scopes can run concurrently. Entry adds its explicit access reservation without changing this rule for operations issued inside it.

## Static external mutation tree

`ContextChain(initialValue, operationContext, mutationAccessTree = undefined)` follows the compiler's finite tree of named static paths during the initial synchronous import transaction. Nodes are own String-keyed maps with `{}` endpoints. The compiler supplies no runtime metadata and retains ownership of its unchanged input. [integration.md](integration.md#compiler-construction-of-the-mutation-access-tree) defines construction.

Follow only requested original own data placements. Missing values, primitives, Errors, Functions, accessors, and Promise/thenable sources contribute no scope. A thenable is not directly accessible even if ordinary import has synchronously delivered its value. Ordinary import continues its usual thenable processing independently. Discovery invokes no getters, enumerates no unrelated native subtree, and consumes one compiler-tree edge at each recursive step; cycles require no extra discovery walk.

At a managed node, reuse staged/admitted category facts and retain only connecting paths to external scopes. At the first external node, record its exact location and continue through requested native data properties to discover nested external scopes. A previously unadmitted native object reached in that region stays external for this purpose; stage its external admission with the registration. Never reclassify an already-managed identity. Such a managed endpoint adds no external scope and cannot grant native access to managed storage. Prune managed endpoints and empty connecting branches. Do not promote an entire managed branch merely because it contains external state.

Every visited external object on a requested route can be a scope, including a branch with children. No endpoint-used flag is required. Stage identity-to-location proposals and all related admission changes atomically. Two distinct selected paths to the same exact external identity fail the import segment with `ExternalLocationConflict`; finite selected cyclic aliases obey the same rule. Abandoned discovery commits no admissions, sharing, versions, tree nodes, or registrations, and its pending import callbacks cannot publish. Independent valid context registrations instead invalidate their shared identity binding at commit as described below.

Discovery below a native node stays inside the existing import reflection boundary. A supported own-descriptor or other required host-reflection failure produces ImportReflectionFailed at the context-import operation and abandons every staged admission and registration; an existing fatal retains its normal precedence. Inspect only compiler-named own data placements. Never enumerate native ownKeys to discover scopes or invoke a getter. Internal compiler-tree shape remains trusted.

### Runtime nodes and identity validation

Keep child property maps separate from internal fields by placing all runtime facts behind one internal Symbol. A node can have children and an external location record simultaneously. Its internal record contains canonical location/provenance, the external identity binding entry when applicable, reservation aggregates, and owned poison/error-summary state. Connecting managed namespace nodes participate in reservations and canonical managed-path capture but grant no external mutation authority. Derive current namespace poison at that capture where possible; a retained placement reference follows canonical publication, never an unrelated copy. Do not reserve public child names such as `path`, `context`, or `__proto__` for metadata. Store child keys as safe own properties.

The location is fixed for the execution. Its node identity and binding entry distinguish the original context route, and its path records the canonical static keys. Nodes retain no reference to the context Chain. Entered Chains refer to the same nodes, not copied registration trees. At a native access, compare the reached identity's execution-local binding entry with the selected location. Supported off-path access produces local poison. Host replacement of a fixed identity violates the support boundary and has no diagnostic guarantee. Keep the actual method receiver operation-local; a suffix receiver need not be a registered scope. Add no second receiver registry or mutable-node discovery cache.

Registered identities and the placements connecting them cannot be replaced, deleted, or moved. Unregistered ordinary native properties, objects, and Arrays may change within the selected authority. Structural operations on managed ancestors must preserve those fixed paths; ordinary sibling properties remain mutable. Managed and native Array length writes reject truncation that would remove registered indexes before writing; native conversion and validation retain their host semantics. Non-index native properties do not constrain Array length. A managed Array-wide bang, including a controlled push, remains invalid when it covers registered mutable resources; ordinary index appends and length growth use narrower placement authority. Poison and entry retain the underlying value and never write placeholders into native storage. Commit never grows or prunes the tree in response to Promise delivery, COW, repair, or binding conflict.

## Identity binding map

One execution-local WeakMap maps each registered external identity to its valid location or permanent conflict Error. The corresponding tree node owns ordering and repairable poison. Conflict is not repairable poison and repair creates no authority.

Commit these identity bindings atomically with initial context import, before any operation can use the context. Binding does not wait for the first observation, mutation, or reservation. A copy therefore has no authority even when the original location has never been used. An empty ordering frontier means no pending work, not an unregistered identity. Store no registration flag on the native object.

| Reached state | Outcome |
| --- | --- |
| No registration | Observation-only external behavior; no mutation authority |
| Correct registered canonical location | Reserve the selected tree scope |
| Registered identity reached through an unrelated Chain or alias | Local `ExternalLocationConflict`; do not poison its legitimate location |
| Competing independently committed context registrations | Shared permanent binding Error; neither context gains precedence |

Import, inert storage, and managed copying create no registration. Regular-Chain import before or after a context does not invalidate that context. Pending off-path use rechecks authority before native access. Completed host effects or exposed results are not revoked retroactively; no reverse alias list or exposure history is maintained. Each execution has independent bindings; a mutable host identity must not be coordinated by multiple executions.

When a valid binding becomes conflicted at import commit, use its previous location before replacing the binding to propagate nonrepairable Error presence through that existing tree. Seed the newly committed location's summary from the same conflict. Further competing contexts seed their own paths; previously conflicted paths already remain marked. This needs no list of aliases or reverse placement registry. Repair recomputes presence from remaining own poison, child membership, and binding conflict, so clearing repairable state cannot hide permanent conflict.

## Routing and capture points

Retain two locations: the first crossing from managed into native state, and the selected registered external scope. The first determines boundary conversion; the second determines ordering, poison, and mutation authority. Traverse only the requested tree path to select the scope, then perform native reflection after its prerequisites. Do not acquire one reservation per encountered external object.

An explicit external `!` prefix selects its registered node. A deeper unregistered suffix remains within its nearest registered external scope. Default external property mutations and observations select the deepest registered prefix of the containing/receiver path; a final read of a registered resource consumes that resource's subtree. A parent `!` deliberately widens authority and locking to the parent. `apis.db!.init()` therefore differs from `apis!.db.init()` when both locations are registered. A managed `apis` cannot be such a widened mutation scope, but can be an entered namespace.

Every registered location actually selected or crossed requires a static source prefix, not merely resolved String/Number keys. Preserve `firstDynamicSegment` through entry and relative-path composition. Keys within an unregistered native suffix may be dynamic but cannot dynamically select a registered descendant; reject that use before accessing the descendant. Dynamic invalid observations return local poison. Invalid mutations poison the deterministically selected scope/static prefix under the ordinary mutation-failure rule, without candidate reservations. Previously encountered poison takes precedence. A tree containing child scopes must not silently normalize a dynamically selected child into static authority at its parent.

Capture explicit inputs, source provenance, and the issuing entry view at issuance. Derive statically selected coverage from the fixed tree without native reflection, capture its external predecessors, and publish one reservation before managed gates can suspend path capture. Continue managed path capture immediately through its ordinary FIFO/version machinery, without awaiting external predecessors first. Native work, subtree metadata inspection, and entry callbacks require both that captured managed state and the reservation's predecessors. Revalidate binding authority before deferred native access; never reserve again or recapture later predecessors. Ordinary managed lookup, export, and method preparation consume no native subtree merely because their value contains registered identities, so add no covering reservation for them.

Managed gates can arise from entry, pending path selection, structural publication, poison, or repair. They are not evidence that a command belongs to an entry view; only its issuing Chain grants that view. Waiting for a gate grants no ownership of it or of later outside reservations. Capture canonical managed placement state, including its gate/version and poison, at the operation's ordered path turn. After an external predecessor wait, revalidate identity binding authority but do not reread later managed gates or replace the captured namespace state with a newer version. External scope poison is different: read it after external predecessors complete, under the held reservation. Earlier pending managed publication remains visible through its captured version; later managed publication cannot become an earlier command's prerequisite. Authorized entered commands use their private managed path and inherited reservation view.

For example, a native command N may reserve db while waiting for an earlier native operation. A later mixed entry E gates a managed ancestor and reserves behind N. N must not acquire E's later managed gate on resumption: E already waits for N. This requires the right capture point, not a graph for bypassing dependent gates. Retained copies still have no native authority; an old managed capture is not a canonical-location credential.

Promise-valued managed selection belongs to Phase 10. Before installing a selection gate at a managed prefix containing registered locations, establish that prefix's external ordering position in the same issuance turn. A later statically selected native command must neither overtake that protection nor become its predecessor. Phase 10 must implement and verify the handoff from protected prefix to selected target, preserving narrow sibling availability once selection completes. Evaluate reuse of ordinary gate/reservation publication; do not introduce speculative child reservations, late acquisition behind later work, or a second scheduler. The fixed-route kernel alone does not implement this unresolved-selection handoff.

## External phases

One completion represents an operation's required external effects and boundary processing. Its wait is fulfillment-only and carries no poison. Fatal failure never resolves, rejects, or cancels internal reservations; public fatal-result handling remains separate.

Propagate an undominated pending reservation frontier up the tree, without child counters or descendant scans. A node distinguishes direct observations, direct mutations, subtree observations, and subtree mutations. These are four conflict sets, not four schedulers. A subtree set includes direct work at that node. Each frontier completion participates in its selected node's direct set and the matching subtree set on that node and each ancestor. Connecting managed nodes participate for mixed entry and guard transitions. The frontier represents ordering dependencies; it is not an inventory of every still-running operation.

| New operation at node N | Earlier dependencies to capture |
| --- | --- |
| Observation | N's subtree mutations; direct mutations at strict ancestors |
| Mutation or repair | N's subtree observations and mutations; direct observations and mutations at strict ancestors |

Strict-ancestor lookup excludes their subtree sets, which include unrelated siblings. A whole-parent observation waits for descendant mutations and blocks subsequent descendant mutations; it is not equivalent to a descendant announcing activity at its parent.

Capture and deduplicate predecessor completions before adding the operation's own completion. Form a fixed wait from that captured membership using ordinary guarded composition. Later additions cannot extend it. A new mutation, including repair or exclusive entry, can replace earlier frontier entries at its own scope or descendant scopes after capturing them: it waits for those entries, and every later operation that would conflict with them also conflicts with it. Remove their direct and propagated memberships in this same view, then publish the new mutation. Retain strict-ancestor and unrelated entries; observations do not replace mutations, because later observations would not wait for the replacement. Never prune another entry view's frontier. This makes a queued same-scope write stream a dependency chain instead of capturing every preceding write again.

Frontier replacement does not finish an operation, release its resources or entry lifetime membership, clear poison, or alter waits already captured. The original completion still settles at its real last-use point; cleanup idempotently removes any membership not already replaced. Each independently finished completion removes itself even while siblings remain pending. Use removable sets or an equivalent bounded representation, with no rolling Promise.all(previousFrontier, newCompletion) history. Dependency records carry no receiver/result payload or settled history. Bound work to selected paths, frontier memberships, and dependencies retained by unfinished operations; do not add a general transitive-dependency graph or retain all pending writes as an alternative scheduler.

An empty set contributes no wait. Do not seed it with an already-fulfilled Promise or force ready native work through a microtask. A synchronously finished operation removes its own membership in the same transition without clearing another operation's pending membership. Use the operation's existing completion transition, with no parallel ready-result transport. Consecutive ready calls with no conflicting pending work retain common sync-first behavior.

For config.init(); db.addUser(); reset(); db.read(), the sibling writes capture no dependency on each other. Reset captures both through the parent's subtree membership and publishes its own direct mutation reservation. The later read captures reset. Recording child work at a parent neither blocks siblings nor includes later children in reset's captured prerequisites.

### Entered branches

Mixed entry remains supported. A mutating managed entry gates its selected placement through ordinary versions and path COW and reserves exclusive external access to its covered subtree. External-root entry uses the same tree reservation without native-property or contextual-binding gates. Every read-only entry uses observation coverage; managed read-only roots also keep their lease. Other observations overlap, while conflicting mutations wait. Unregistered observation-only external identities acquire no mutable-resource reservation. Explicit unregistered native-property entry is invalid; compiler selection chooses the deepest enclosing registered node.

Entry reserves a selected location without consuming its value. Poison at the selected managed or external target does not skip its callback: transfer the selected placement state, including any managed recovery baseline, so contained inspection, permitted replacement, or explicit repair can run. Poison on a strict ancestor and invalid binding still block selection. Ordinary contained reads/calls check poison normally; readonly entry cannot repair or mutate. Successful entry setup adds no poison, while failed mutating target selection retains its prescribed scope effect.

Contained work must not rejoin an outside reservation that is waiting for that entry. Use a reservation view scoped to the entry's covered subtree: the outer reservation captures earlier global work; contained operations use the same frontier algorithm within that view. Entry views carry inherited authority and the covered node, not a second native queue or copies of data/registration nodes. Before invoking an entry callback, wait for its captured predecessors and recheck its selected binding and strict-ancestor external own poison. Only then can contained work use the private view without bypassing earlier outside effects. Target/descendant poison does not prevent entry for inspection or repair. Empty prerequisites preserve synchronous invocation. Nested entry publishes a reservation in its parent's view and applies the same rule. Work cannot escape its covered subtree or readonly capability; reference arguments to Cascada functions use these same entries. Do not grant ownership of unrelated outside reservations.

Each command with statically selected external coverage creates its reservation and enclosing-entry lifetime membership together at issuance, before managed gates can wait. Its completion represents captured predecessors plus required effects and boundary processing. An early managed selection failure may expose its Error before those predecessors finish, but the reservation completes only after they do; otherwise a skipped writer could break the dependency chain it replaced. Ready work finishes synchronously and retains no pending-completion history. Independent nested results do not extend access.

Managed-only work has no external completion merely because a later reflection failure might poison a managed prefix. Such failure uses ordinary placement publication and does not mutate native state or acquire broader external authority. Preserve the original managed Error without also poisoning the reserved native scope. Existing captured native work keeps its ordered namespace; repair takes the ordinary covering reservation before clearing metadata.

Closing an entry stops new issuance and captures its outstanding command/reservation completions. Release outer coverage only after those effects, including already-issued nested entries and delayed selection, finish. Later contained work of an already-active nested entry remains owned by that entry. Callback result and managed graph publication retain their separate existing lifetimes. A mixed entry may publish a managed root whose ready sibling is usable while a native child remains pending; its native paths still obey the live reservations. Never hold the entire managed root gate until all native descendants settle.

This view is only an ownership boundary for the common external reservation algorithm. Managed child gates and property versions still carry managed pending work after parent publication. Before choosing a representation, verify nested child entry surviving parent callback closure, a later parent reservation waiting on a child whose callback continues issuing work, sibling progress, and fatal resumption. Do not preserve the old dependency-bypass graph alongside this view after cutover.

Multiple reference arguments need the [batch entry protocol](enter.md#multiple-reference-arguments). A ready argument reserves at issuance even when another disjoint argument is behind managed selection. An entry effect completion alone records lifetime and cannot prevent later resource work from overtaking it. Phase 13 implements batch path selection; the common reservation kernel remains capture-before-publish and composable.

## Poison and repair

Invalid dynamic selection publishes failure at its known static owner. If that owner is external, reserve its tree node and store tree poison; never replace its managed binding placement with an Error. If the known owner is managed, use its ordinary placement recovery. An invalid repair request follows the same failure path and cannot clear existing poison or select a dynamic native descendant.

Each failure belongs to exactly one selected scope. External nodes store ownPoison separately from completion dependencies; native storage remains unchanged. A descendant Error is never installed as ancestor-owned poison. A failed managed prefix uses placement poison only, without late acquisition of broader external coverage or duplicate tree poison. Maintain the set of immediate child branches containing poison at each node, propagating empty/nonempty changes upward without occurrence counts or persistent compounded wrappers. The tree is acyclic even when the host graph is not. Binding conflicts remain permanent errors and are included in contextual queries separately.

Use the same presence-transition rule as the managed query summaries: propagate to a parent only when a child branch changes between empty and nonempty. Here every child has one parent and there are no cycle cuts or multiplicities. Reuse that rule without importing the managed refcount/index machinery or building a generic graph propagation framework.

An operation targeting N checks own poison on strict ancestors, then required poison in N's subtree after its conflicting predecessors complete. Ancestor-owned poison blocks all descendants with its original Error. A sibling's Error does not block a child operation through a derived parent summary. Whole-parent work consumes the complete subtree Error union and skips native code when blocked. Observations add no poison. A blocked mutation likewise adds no new poison.

A parent metadata query holds one covering observation reservation and reads the required child records under it. It never reacquires child reservations behind a later parent mutation already waiting for that query. Capture original Error references before releasing that reservation; later repair cannot alter the returned collection.

Metadata queries and repair validate the remaining native suffix's path segment values without reading native properties or invoking coercion. Encountered scope poison still blocks ordinary queries first. Repair validates before clearing its selected poison; invalid keys leave that poison intact.

`hasError` can stop on a proof. `getErrors` gathers original Errors from the selected external metadata subtree, including independent child poison even when its selected root also owns poison, without inspecting native contents or awaiting retained managed data. Combine through the existing idempotent Error factory: null for none, the exact original Error for one, and a flattened compound preserving every distinct cause/source/kind for several. Do not repeatedly wrap or reattribute propagated Errors. Access blocked at a poisoned strict ancestor returns that blocker instead of navigating into its subtree. Ordinary managed guard queries remain terminal at that guard; this external metadata collection does not reopen hidden managed recovery graphs.

Repair-only reserves exclusive access, preflights target/placement selection and checks registration and poison above its target, then clears repairable poison throughout the selected subtree and updates ancestor summaries. It invokes no native method or external-resource read/write and returns undefined; once valid and reachable, it has no recoverable failure of its own. Permanent binding conflicts remain; a subsequent whole-subtree call still sees a conflicting child and cannot run. Repair-and-call performs that clearing first under the same exclusive reservation, then normal preparation and invocation. A new preparation/call failure poisons the selected scope; deliberately cleared old Errors are not combined back in. Repair is neither rollback nor evidence that native physical state was restored.

Only repair's clearing step bypasses selected-subtree poison. Subsequent invocation uses ordinary subtree checks, including permanent descendant binding conflicts and conflicts introduced while arguments were pending. Repair mode never weakens those checks.

All managed mutations preserve their pre-operation logical scope through ordinary ownership and COW. A failure, including invalid mixed-scope selection, discards working changes and stores the original Error with its retained baseline in owning-placement metadata. Native descendants remain blocked by canonical namespace poison. Repair exposes that baseline and clears covered external subtree poison without native rollback. Canonical namespace capture or a retained tree reference follows the authoritative logical placement through ancestor COW and entered publication. Repair of an unrelated copy changes only that copy. The tree stores neither another Error nor a failed working receiver; already-issued operations retain their earlier ordered captures.

## Host boundary

External methods operate on native receiver-owned state, not raw managed parents, siblings, or aliases. Observation-only external references in managed methods remain opaque: retain/compare them if permitted, but do not inspect or mutate their host state. All host arguments use the existing preparation/export and argument ownership contract; source position above or below `!` creates no additional mutation permission. There is no special ancestor-argument mode.

External calls and property writes use common guarded host boundaries and action-specific Error kinds. A native setter/reflection throw or false write/delete poisons the selected mutation scope; exporting an Error-valued RHS skips native storage and poisons that scope. Every observation Error affects only its result. Already performed native effects are not rolled back.

Method results use ordinary causal import, not implicit snapshots. Return independent managed data or relinquish mutation of it. Ready results remain available while nested Promises are pending. Existing managed results are read through logical placements and preserve their source versions. Result-specific validation may need selective borrowed-container copies; retain that mechanism and its aliases, cycles, source attribution, and independent nested-result lifetime. No ready-only result restriction or full-result await is introduced.

Borrowed-container copies preserve complete source placement state, including recovery baselines and absence, both at initial capture and after captured versions settle. Restoring or mutating a result copy cannot change its source's retained baseline. Merely returning a standalone Error transfers no recovery state, and newly created result-boundary Errors acquire no source recovery baseline.

A capability escape newly detected while admitting the direct result of a mutating call poisons its scope. Collect those violations where import detects the escaping identities, separately from all Errors required by the result. Ordinary result Errors, previously contextualized capability Errors carried as data, and failures discovered in independently pending descendants remain result-only. Error kinds describe failures; they do not determine a later operation's mutation effects.

Registered mutable identities remain receiver capabilities. Host-input export, direct extraction, callback exposure, and method-result escape fail through existing capability rules. Traversing from a selected parent into its registered descendant under enclosing authority is not off-path use, but each reached fixed identity must match its registered location. Hidden aliases, sibling-crossing effects, and later receiver access from independent nested result work remain excluded host behavior.

Registration also determines extraction behavior. If apis.db.config is registered, lookupPath of that object returns ExternalCapabilityEscape rather than a detached copy; traversal through its canonical route to config.timeout may still return the scalar value normally. An unregistered apis.db.other can be snapshotted when its data satisfies the snapshot contract. Snapshot traversal encountering a registered identity at any depth fails capability validation rather than copying its native interior. Observation failure poisons only the returned result. Managed-parent lookup may still retain an inert reference, without transferring authority.

## Managed and external ownership

Managed lookup, argument capture, import, and retained results keep ordinary sharing, leases, COW, and placement versions. Copying a parent to another owner grants no native authority. Controlled mutation scope selection consults only the canonical external tree at its route; do not scan unrelated managed data, await an unused pending alias, or maintain an identity-containment flag to reject inert references. Native managed methods consume their complete receiver and reject registered mutable identities during that existing preparation, including off-path aliases. These checks protect different boundaries: an inert reference is safe to retain as data but unsafe to give native code as an accessible receiver child.

Entry grants access ordering only. Gate installation uses ordinary ancestor COW when sharing or leases require placement isolation; an unprotected ancestor needs no copy. Entering does not eagerly deep-copy its selected value. Actual contained managed mutation decides its own COW. Source origin, Error attribution, and previously captured outputs remain unchanged through poison and repair.

## Snapshot transaction

Property reads from mutable external state hold their observation reservation through direct availability and detached snapshot construction. Snapshot only the requested result graph; a direct Promise may resolve first, but nested pending data is invalid and is not subscribed. Native sources are not admitted before snapshot classification. Already-managed sources use logical property versions and Array projections, including sparse topology and native logical length. Snapshotting does not allow direct native mutation or traversal into raw managed storage by host methods.

Property-path observation may cross between native state and already-managed logical data more than once. Choose the read mechanism for each reached identity; an external-to-managed-to-external-to-managed path is valid when every access satisfies its ordinary authority and readiness rules. This grants no native call/write access to managed storage. Mutating traversal stops as soon as it would cross managed storage, so an external identity farther down the route cannot regain mutation authority. Readiness validation at intermediate native values and managed snapshot placements never invokes then or admits the source; it preserves the relevant path/snapshot Error kind. Only a final native property value has the direct-Promise availability exception.

Copy managed-compatible records, Arrays, and class state with their supported prototypes, aliases, and cycles; preserve Functions and permitted exact observation-only leaves. Reject registered mutable capabilities wherever encountered. Stage copies and admissions atomically, collect every discoverable Error, and discard incomplete output on failure. Ready reflection failure receives the snapshot boundary's Error kind; internal invariant failure remains fatal. Share traversal with export only where capture and readiness semantics match; no generic mode-driven copier is required.

Observation-only native property results retain their separate external-root import policy and require no mutable reservation. Outbound export uses its normal complete Error collection and independent copies. End source reservations after required capture and processing, not after unrelated nested result availability.

## Verification boundary

Phase 9F-A verifies the conflict table, fixed-location discovery below external nodes, source-staticness, nested/mixed entry views, complete metadata Error unions, recursive repair, and owner-isolated guards together. Preserve existing admission atomicity, context/regular-Chain import-order behavior, immutable outputs, action-specific errors, supported Proxy behavior, and public fatal-result ownership. Do not claim that a smaller helper proves an end-to-end simplification; delete superseded gate indexes, single-owner cursors, and binding gates only as their behaviors pass through the common replacement.
