# External Context Ordering Architecture

**Phase 6 status:** complete and independently reviewed. Registration retains the first valid binding. Metadata queries and repair use ordered version trees; actual native work retains hierarchical reservations. Finished observations release their reservations at last use. Computed canonical metadata selection and failure-preserving repair share the common path cursor.

The developer-facing contract is [data-limitations.md](data-limitations.md). The native reservation foundation comes from [Phase 9F-A](first-principles-conformance-plan.md#phase-9f-a-scope-coordination-and-managed-rollback). Phase 6 adds metadata publication and selection without a second native dependency representation.

## Model

Managed state uses leases, sharing, COW, and placement versions. External state retains exact native identities; its access reservations and poison live in the external mutation tree, never in native properties. Observation-only external identities remain unlocked under their read-only host contract.

A mutable external subtree can contain nested registered scopes. `apis.config!.init()` and `apis.db!.addUser(1)` may overlap, while `apis!.reset()` excludes both subtrees when `apis` is external. Each mutation may change only state within its selected external scope. Parent-owned native methods may change descendant state but preserve every registered identity and location. Hidden writable overlap between supposedly independent siblings violates the host contract.

A managed mutation scope cannot cover canonical registered mutable external locations. Reject that scope before mutation and poison its selected managed root, preserving its value for repair. An inert external alias at another location does not forbid controlled managed writes, but grants no external observation or mutation authority. Native managed receiver preparation independently rejects registered mutable identities in the complete receiver. Observation-only external references remain permissible opaque leaves. Entry reserves access, may select a mixed branch, and grants no mutation authority. Its contained operations independently obey these scope restrictions.

Two scopes overlap when one is an ancestor of the other or they are equal. Ordinary external operations conflict exactly when their scopes overlap and at least one mutates. Observations can run concurrently; disjoint sibling scopes can run concurrently. Entry adds its explicit access reservation without changing this rule for operations issued inside it.

## Static external mutation tree

`ContextChain(initialValue, operationContext, mutationAccessTree = undefined)` follows the compiler's finite tree of named static paths during the initial synchronous import transaction. Nodes are own String-keyed maps with `{}` endpoints. The compiler supplies no runtime metadata and retains ownership of its unchanged input. [integration.md](integration.md#compiler-construction-of-the-mutation-access-tree) defines construction.

Follow only requested original own data placements. Missing values, primitives, Errors, Functions, accessors, and Promise/thenable sources contribute no scope. A thenable is not directly accessible even if ordinary import has synchronously delivered its value. Ordinary import continues its usual thenable processing independently. Discovery invokes no getters, enumerates no unrelated native subtree, and consumes one compiler-tree edge at each recursive step; cycles require no extra discovery walk.

The approved [stable-category correction](runtime-evolution-plan.md#approved-receiving-rule-stable-categories) replaces registration's forced external classification. At a managed context node, reuse staged/admitted facts and retain connecting paths to external scopes. At the first external node, record its exact location and continue through requested native data properties using ordinary declarations/defaults. Stop an entire discovery suffix when it crosses from external ownership into managed data: deeper external descendants cannot regain native mutation authority through that route. Ordinary managed prefixes before the external owner still connect to their selected resources. Do not admit mutable native data in place, reclassify an admitted identity, or promote a managed branch because it contains external state.

Every visited external object on a requested route can be a scope, including a branch with children. No endpoint-used flag is required. Stage identity-to-location proposals and all related admission changes atomically. Validate every proposal against both this transaction's selected identities and the execution's existing bindings before committing any admission, managed topology or registration. Two distinct selected paths to the same identity, or any claim on an already registered identity, reject the entire new context import with ExternalLocationConflict at that import operation; finite selected cyclic aliases obey the same rule. Abandoned discovery commits no admissions, sharing, versions, tree nodes or registrations, and its pending import callbacks cannot publish. Earlier contexts and their metadata remain unchanged, and otherwise fresh identities in the rejected transaction remain unregistered.

Discovery below a native node stays inside the existing import reflection boundary. A supported own-descriptor or other required host-reflection failure produces ImportReflectionFailed at the context-import operation and abandons every staged admission and registration; an existing fatal retains its normal precedence. Inspect only compiler-named own data placements. Never enumerate native ownKeys to discover scopes or invoke a getter. Internal compiler-tree shape remains trusted.

### Runtime nodes and identity validation

Keep child property maps separate from internal fields by placing all runtime facts behind one internal Symbol. A node can have children and an external location record simultaneously. Its internal record contains its parent and depth, the exact external identity when applicable, reservation aggregates, and versioned poison state. Connecting managed namespace nodes participate in reservations and canonical managed-path capture but grant no external mutation authority. Derive current namespace poison at that capture where possible; a retained placement reference follows canonical publication, never an unrelated copy. Do not reserve public child names such as `path`, `context`, or `__proto__` for metadata. Store child keys as safe own properties.

The location is fixed for the execution. Its node and stored external identity distinguish the original context route, and tree edges encode the canonical static keys. Store depth for routing comparisons without copying complete paths into nodes. Nodes retain no reference to the context Chain. Entered Chains refer to the same nodes, not copied registration trees. Trust the selected canonical node's fixed identity; omit the redundant mismatch comparison for unsupported host replacement. Preserve ordinary path consumption, poison checks and supported native reflection failures before using that identity. Without a canonical node, execution-local registration membership rejects an off-path registered identity. Supported off-path access produces local poison. Host replacement of a fixed identity violates the support boundary and has no diagnostic guarantee. Keep the actual method receiver operation-local; a suffix receiver need not be a registered scope. Add no second receiver registry or mutable-node discovery cache.

Registered identities and the placements connecting them cannot be replaced, deleted, or moved. Unregistered ordinary native properties, objects, and Arrays may change within the selected authority. Structural operations on managed ancestors must preserve those fixed paths; ordinary sibling properties remain mutable. Managed and native Array length writes reject truncation that would remove registered indexes before writing; native conversion and validation retain their host semantics. Non-index native properties do not constrain Array length. A managed Array-wide bang, including a controlled push, remains invalid when it covers registered mutable resources; ordinary index appends and length growth use narrower placement authority. Poison and entry retain the underlying value and never write placeholders into native storage. Commit never grows or prunes the tree in response to Promise delivery, COW, repair, or rejected registration.

## Registration membership

The execution advances one registration revision after each successful nonempty commit. Native access checks every newly crossed identity immediately and remembers the last revision at which its retained prefix was checked. Recheck that prefix before further host access only when the revision changes. This bounds uninterrupted path work without replaying getters; it also covers waits inside managed portions of a mixed path. Rejected and empty registrations do not advance the revision. Identity membership remains the authority, and retained identities keep their existing last-use release.

Use one execution-local WeakSet of registered external identities. Canonical routing already supplies the selected tree node and its stored fixed identity, without a repeated identity comparison; registration membership rejects a registered identity reached without its canonical node. There is no identity-to-node lookup, binding-entry object or WeakRef. Trust the existing Chain/execution and route invariants rather than adding another registration token or shape check. A live context, entered reference or pending operation retains its required tree normally; a live host identity alone cannot retain that tree. WeakSet membership persists while the identity is live, even after its original location is collected, so collection never permits rebinding.

Commit registration membership atomically with initial context import, before any operation can use the context. Binding does not wait for the first observation, mutation, or reservation. A copy therefore has no authority even when the original location has never been used. An empty ordering frontier means no pending work, not an unregistered identity. Store no registration flag on the native object.

| Reached state | Native-access outcome |
| --- | --- |
| No registration and no enclosing registered external authority | Observation-only external behavior; no mutation authority |
| Correct registered canonical location | Reserve the selected tree scope |
| Registered identity reached through an unrelated Chain or alias | Local `ExternalLocationConflict`; do not poison its legitimate location |
| Later context proposes an already registered identity | Reject that entire context import before commit; the first valid location remains valid |

Import, inert storage, and managed copying create no registration. Regular-Chain import before or after a context does not invalidate that context. Pending native use rechecks registration membership for every crossed external identity reached without its canonical node, including the root, intermediates and receiver. Any of them may be first registered elsewhere during an argument or key wait; continued access must then fail locally before further host access, while the new canonical location remains usable. Keep these identity dependencies operation-local while further live access depends on that route. Recheck identities directly without rereading getters or rebuilding the path, and release the captures at their last authority check or when host access is abandoned. Already captured managed receivers do not retain spent native-prefix dependencies. Completed host effects or exposed results are not revoked retroactively; no reverse alias list or exposure history is maintained. Each execution has independent bindings and ordering; mutable resource reuse across executions requires [host-guaranteed non-overlapping access lifetimes](data-limitations.md#external-reuse-across-executions). These bindings neither detect nor enforce cross-execution exclusion.

Commit only fully validated new bindings, synchronously with the initial context transaction. No host action or suspension occurs between final validation and commit. A later duplicate proposal returns an ordinary contextual import Error; it never changes existing registration membership, publishes poison to either resource tree, or invalidates a pending canonical call. Use the same validation path for duplicates within and across contexts. Registration rejection needs no conflict publication, summary propagation or repair special cases, and no compatibility state, alias list, finalizer or reverse placement registry. The earlier [diagnostic audit](phase4-review.md#binding-diagnostics-and-remaining-simplifications-2026-10-21) records the previous policy.

A rejected context import and an existing context's mutation failure have independent causal boundaries. Registration rejection adds no poison to the valid context and cannot suppress a pending mutation's eventual scope failure. Existing blockers instead travel in result-only mutation outcomes and add no poison. Completion uses that outcome rather than rechecking current blockers to decide failure ownership. Native access preserves canonical route authority and checks current membership for identities crossed without their canonical nodes. Trust immutable canonical bindings; no binding-error capture or repeated canonical identity comparison remains. The late-first-registration check applies before further live host access after a wait, not only to the final receiver. An unregistered alias alone grants no mutation authority; metadata-only repair neither accesses the host nor acquires such authority.

## Routing and capture points

Retain two locations: the first crossing from managed into native state, and the selected registered external scope. The first determines boundary conversion; the second determines ordering, poison, and mutation authority. Traverse only the requested tree path to select the scope, then perform native reflection after its prerequisites. Do not acquire one reservation per encountered external object.

An explicit external `!` prefix selects its registered node. A deeper unregistered suffix remains within its nearest registered external scope. Default external property mutations and observations select the deepest registered prefix of the containing/receiver path; a final read of a registered resource consumes that resource's subtree. A parent `!` deliberately widens authority and locking to the parent. `apis.db!.init()` therefore differs from `apis!.db.init()` when both locations are registered. A managed `apis` cannot be such a widened mutation scope, but can be an entered namespace.

Every registered location selected or crossed for native access requires a static source prefix, not merely resolved String/Number keys. Preserve declared dynamic provenance through entry and relative-path composition. A Promise key also ends the static prefix even when provenance is omitted or declares a later boundary; the existing route walk stops at non-String/Number input without probing thenability. Resolution never restores static authority. This makes host authority and conflicting-effect coverage knowable at issuance; it is an intentional restriction, not a consequence of determinism alone. Dynamic native suffixes cannot cross another registered location. Canonical metadata-only queries and repair may use computed or Promise-valued keys under the protocol below. Dynamic keys never create registrations or permit extraction of a resource identity. Forbidden host operations use the approved ordinary local-failure rule; earlier poison keeps its ordinary precedence.

A forbidden native observation uses the immutable authority of its statically reached prefix and ancestors and consumes only their own poison captured at its ordered position. No unselected child poison or work contributes. Known forbidden access needs no host reservation merely to read this runtime-owned state. An initially unresolved native suffix can still require issuance-time host coverage; once its required prefix-metadata consumption finishes and no host access remains, release the read reservation under the immediate-completion rule below. Actual host access rechecks membership for crossed identities not justified by their canonical nodes. Metadata-only queries selecting a canonical registered node are permitted and are not forbidden native observations.

Capture explicit inputs, source provenance and the issuing entry view at issuance. Derive statically selected host coverage from the fixed tree without native reflection and publish its reservation before managed gates can suspend path capture. Capture managed state and the required external metadata view at that ordered turn, without first waiting for host predecessors. Native work requires captured namespace state, its metadata blockers, native predecessors and current registration checks for its retained noncanonical native path dependencies. Never reread later managed gates or metadata versions as new prerequisites. Metadata queries and repair use versioned state without host reservations of their own; fixed entry retains its declared native coverage.

Managed gates can arise from entry, pending path selection, structural publication, poison or repair. Only the issuing Chain grants an entry view. Waiting for a gate grants no ownership of it or of later outside reservations. Preserve the captured canonical namespace and metadata view after suspension. Binding authority is different: retain the current registration-membership check for access without a canonical node, while trusting a canonical node's fixed identity. Ordinary path, poison and supported reflection boundaries still apply before host access. A previously unregistered alias can become registered elsewhere while waiting and must then fail locally. A duplicate registration cannot revoke the first valid canonical binding or change its metadata. Authorized entered commands use their private managed and metadata view; none may wait on their own enclosing future completion.

For example, a native command N may reserve db while waiting for an earlier native operation. A later mixed entry E gates a managed ancestor and reserves behind N. N must not acquire E's later managed gate on resumption: E already waits for N. This requires the right capture point, not a graph for bypassing dependent gates. Retained copies still have no native authority; an old managed capture is not a canonical-location credential.

Promise-valued consuming path selection combines ordinary managed gates and captures, versioned external metadata, and existing reservations for native access. A managed lease alone does not capture external metadata. The [implementation evidence](runtime-evolution-plan.md#implementation-and-verification-evidence) covers static and unresolved selection, sibling progress and bounded retained history.

A later statically selected native command must neither overtake earlier selection protection nor become its predecessor. The [ordering witnesses](phase6-selection-experiments.md#ordering-witnesses) cover true same-scope and ancestor dependencies while releasing unrelated siblings. Changing frontier membership cannot selectively release waiters that already captured one shared completion. Versioned metadata supplies captured publications instead of query/repair reservations; it does not remove genuine ordering obligations. Consult the user before weakening progress, restricting dynamic repair, or adding another dependency representation.

Entry reference capture is different: an unavailable key remains on the private reference, and the available managed anchor and its external coverage stay fixed even after key delivery. Do not consume the key to narrow entry. Its contained commands perform ordinary consuming selection in their issuing entry view; managed publication and covered external work keep their separate completion rules. Unrelated work outside the fixed coverage remains available.

## External phases

One completion represents an operation's required external effects and boundary processing. Its wait is fulfillment-only and carries no poison. Fatal failure never resolves, rejects, or cancels internal reservations; public fatal-result handling remains separate.

Propagate an undominated pending reservation frontier up the tree, without child counters or descendant scans. A node distinguishes direct observations, direct mutations, subtree observations, and subtree mutations. These are four conflict sets, not four schedulers. A subtree set includes direct work at that node. A subtree-consuming operation participates in its selected node's direct set and the matching subtree set on that node and each ancestor. Metadata-only prefix validation instead captures versions; it adds no native frontier membership. Connecting managed nodes participate for mixed entry and guard transitions. The frontier represents ordering dependencies; it is not an inventory of every still-running operation.

| New operation at node N | Earlier dependencies to capture |
| --- | --- |
| Observation | N's subtree mutations; direct mutations at strict ancestors |
| Native mutation or exclusive entry | N's subtree observations and mutations; direct observations and mutations at strict ancestors |

Strict-ancestor lookup excludes their subtree sets, which include unrelated siblings. A whole-parent observation waits for descendant mutations and blocks subsequent descendant mutations; it is not equivalent to a descendant announcing activity at its parent.

Capture and deduplicate predecessor completions before adding the operation's own completion. Form a fixed wait from that captured membership using ordinary guarded composition. Later additions cannot extend it. A new native mutation or exclusive entry can replace earlier frontier entries at its own scope or descendant scopes after capturing them: it waits for those entries, and every later operation that would conflict with them also conflicts with it. Remove their direct and propagated memberships in this same view, then publish the new mutation. Retain strict-ancestor and unrelated entries; observations do not replace mutations, because later observations would not wait for the replacement. Never prune another entry view's frontier. This makes a queued same-scope write stream a dependency chain instead of capturing every preceding write again.

Frontier replacement does not finish an operation, release its resources, discharge enclosing-entry obligations, clear poison, or alter waits already captured. The original completion still settles at its real last-use point; cleanup idempotently removes any membership not already replaced. Each independently finished completion removes itself even while siblings remain pending. Use removable sets or an equivalent bounded representation, with no rolling Promise.all(previousFrontier, newCompletion) history. Dependency records carry no receiver/result payload or settled history. Bound work to selected paths, frontier memberships, and dependencies retained by unfinished operations; do not add a general transitive-dependency graph or retain all pending writes as an alternative scheduler.

A finished read reservation completes immediately without waiting for its captured predecessors. Reads replace no frontier entries; later operations conflicting with an earlier predecessor capture it directly or capture a mutation that replaced it. This applies to waiters already issued before read release and to new waiters, in global and entry views. Mutation/exclusive completion keeps its predecessor wait. The read's own required host access and effect work must finish before release. Any remaining work uses already captured state; the rule does not authorize early reading or cancel unfinished work.

An empty set contributes no wait. Do not seed it with an already-fulfilled Promise or force ready native work through a microtask. A synchronously finished operation removes its own membership in the same transition without clearing another operation's pending membership. Use the operation's existing completion transition, with no parallel ready-result transport. Consecutive ready calls with no conflicting pending work retain common sync-first behavior.

For config.init(); db.addUser(); reset(); db.read(), the sibling writes capture no dependency on each other. Reset captures both through the parent's subtree membership and publishes its own direct mutation reservation. The later read captures reset. Recording child work at a parent neither blocks siblings nor includes later children in reset's captured prerequisites.

### Entered branches

Mixed entry remains supported. A mutating managed entry gates its selected placement through ordinary versions and path COW and reserves exclusive external access to its covered subtree. External-root entry uses the same tree reservation without native-property or contextual-binding gates. Every read-only entry uses observation coverage; managed read-only roots also keep their lease. Other observations overlap, while conflicting mutations wait. Unregistered observation-only external identities acquire no mutable-resource reservation. Runtime entry capture selects the deepest usable static registered node for a native suffix and retains that suffix on the reference. It does not read the native leaf or reject an unused target; actual contained commands enforce ordinary authority, binding, and poison rules.

Entry reserves a selected location without consuming its value. Poison at the selected managed or external target does not skip its callback: transfer the selected placement state, including any managed recovery baseline, so contained inspection, permitted replacement, or explicit repair can run. Poison on a strict ancestor and invalid binding do not skip the callback either; ordinary contained data/native access meets its blockers with their original Error; canonical metadata repair preserves state on failure and clears only covered repairable poison on success. Ordinary contained reads/calls check poison normally; readonly entry cannot repair or mutate. Successful entry setup adds no poison, while failed mutating target selection retains its prescribed scope effect.

Contained work must not rejoin an outside reservation that is waiting for that entry. Use a reservation view scoped to the entry's covered subtree: the outer reservation captures earlier global work; contained operations use the same frontier algorithm within that view. Entry views carry inherited authority and the covered node, not a second native queue or copies of data/registration nodes. Before invoking an entry callback, wait for its captured predecessors. Only then can contained work use the private view without bypassing earlier outside effects. Contained native accesses use immutable canonical authority, current membership checks for crossed noncanonical identities and their captured scope poison. Metadata queries use their captured view; canonical repair clears covered repairable poison without changing registration. None of these checks suppresses the non-consuming callback. Empty prerequisites preserve synchronous invocation. Nested entry publishes a reservation in its parent's view and applies the same rule. Work cannot escape its covered subtree or readonly capability; reference arguments to Cascada functions use these same entries. Do not grant ownership of unrelated outside reservations.

Each command with statically selected native coverage creates one reservation for host ordering and enclosing-entry completion before managed gates can wait. Mutation/exclusive completion retains captured predecessors, including on early failure, because it may have replaced their frontier entries. A finished read completes immediately: it replaced no predecessors, and later conflicts still capture them directly or through a replacing mutation. Finish or capture every required read first; release grants no subsequent live-state access. Entry closure still waits for required contained effects represented in its frontier. Ready work retains no completion history.

Managed-only work has no external completion merely because a later reflection failure might poison a managed prefix. Such failure uses ordinary placement publication and does not mutate native state or acquire broader external authority. Preserve the original managed Error without also poisoning the reserved native scope. Existing captured native work keeps its ordered namespace; repair publishes its ordered metadata transition together with managed recovery.

Closing an entry stops new issuance. Capture its native root frontiers to retain unfinished host work directly or through replacing reservations. Managed child gates and metadata publication versions separately retain their required contained work, including a pending repair after callback closure. At mutating callback closure, hand the captured private metadata view to the enclosing publication, retaining pending nested publications in that view instead of recursively awaiting all contained work. Any unresolved transition that still controls the root or its atomic managed/metadata commit remains represented as pending. Do not add an operation registry. Release outer native coverage after required contained host effects, while metadata and managed publication retain their own lifetimes. Ready managed siblings can remain usable while a native child is pending.

This view is only an ownership boundary for the common external reservation algorithm. Managed child gates and property versions still carry managed pending work after parent publication. Before choosing a representation, verify nested child entry surviving parent callback closure, a later parent reservation waiting on a child whose callback continues issuing work, sibling progress, and fatal resumption. Do not preserve the old dependency-bypass graph alongside this view after cutover.

Multiple reference arguments need the [batch entry protocol](enter.md#multiple-reference-arguments). A ready argument reserves at issuance even when another disjoint argument is behind managed selection. An entry effect completion alone records lifetime and cannot prevent later resource work from overtaking it. [Phase 8](runtime-evolution-plan.md#phase-8-cut-cascada-over-to-the-execution-error-architecture) implements batch path selection; the common reservation kernel remains capture-before-publish and composable.

## Poison and repair

The fixed resource tree describes canonical locations and scope ancestry. Logical metadata has versioned own poison and child branches, including pending earlier publications. Successful canonical bindings are immutable and need no conflict versions. Stable topology, historical metadata and live authority are distinct facts. Share the capture-and-publication pattern with managed placements; do not force resource metadata through managed admission, Array representation or ownership machinery merely to reuse a type.

### Version storage

A reset-only publication may omit its own-poison future when the prior own state is known healthy: success clears it and failure restores that same healthy state. Repair-and-call and entry are general replacements and must retain that future, since their work can publish a new own Error even from a healthy starting state.

`src/external-metadata.js` stores immutable logical subtree versions over the fixed resource topology. Sparse binary child branches copy only the selected route; they never copy or enumerate an unrelated child map. Native mutations publish their own outcome cell. Repair and entry publish subtree futures. Selecting an unavailable component creates its future once on that version; publication delivers only the components already selected. A component has no reference back to its containing version. Later writes retain their own successor branches, and a covering reset replaces the selected view independently of older publishers.

Equivalent versions merge into weighted representatives, following the existing identity-cell pattern. Only the representative owns the payload and pending consumers; aliases resolve to it before use. Merge weight bounds forwarding depth. Versions have only forward links, so ordinary garbage collection releases unreachable history without metadata reference counts, reverse relationships or summary propagation.

Collection consumes selected version branches and collapses a pair to the existing empty state once both children are known empty. This is a permanent fact about that logical version, shared by all its captures; later writes publish successor versions. The first query may traverse healthy topology left by earlier publication, but subsequent queries reuse its empty result. No upward notification or separate validity flag is needed.

Captures and publishers clear the fields they stop using. A pending publisher owns its lazily selected components until delivery; consumers keep only their selected states. Component delivery and forwarding compression use synchronous loops for long histories. Only actual consumers create Promise signals. Merging unavailable versions transfers the flat resolver chain in constant time; usable structure drains it synchronously, without intermediate consumer wakeups or Promise-adoption history. These cells belong to metadata and do not participate in managed admission or native reservations.

### Metadata selection

Canonical contextual hasError/getErrors and repair-only may select a registered scope through ready computed, synchronous thenable or deferred keys. They use the same consumed-key protocol and canonical tree cursor as managed paths, without reading native properties, exporting a capability, creating a registration or scanning candidate children. Off-path aliases have no canonical metadata authority. Stopping at their managed placement uses the [terminal-alias boundary](data-limitations.md#terminal-alias-placement); it is distinct from traversing into or invoking the resource. Readonly entry forbids repair independently of path provenance.

After common route selection, canonical metadata queries and repair consume captured metadata directly. They construct no ExternalAccess and own no native reservation to detach or complete. Key validation belongs to the common segment protocol. Managed and external Error collection still join under the existing query owner; observation-only external property queries retain ordinary native access and import. Entry retains its separately required native coverage.

The metadata cursor advances within its issuance snapshot, releasing unselected branches and resolved healthy ancestors instead of rebuilding ancestor scans. Blocker and collection work retain their own selected states. Native dispatch ends the issuance capture's lifetime independently of the native reservation and outcome publication.

Under an external owner, follow the fixed tree along consumed normalized keys to the deepest registered scope on that path. An unregistered native suffix retains that enclosing scope and receives ordinary key validation without native traversal. Thus querying api.data inspects resource metadata; querying a previously obtained managed snapshot inspects its data instead. A known failed prefix does not consume unused keys; hasError may stop on a sufficient proof, while getErrors retains every dependency needed to determine its complete required Error membership. Computed repair of a resource and computed repair of its containing managed group follow the same authority rule.

### Ordered snapshots and live authority

Capture a logical metadata view at operation issuance in its ordering view, including when target selection is still pending. Earlier native mutations install pending metadata publications at issuance; captures include their eventual success or failure and exclude later mutation and repair publications. An unresolved selection retains the prefix view and consumes only the eventual target. No eager candidate enumeration or late live metadata lookup may replace that capture. Native operations likewise consume their captured blocker state rather than rereading live poison after argument or predecessor waits; current registration membership remains a separate authority check. Repair-and-call continues with its own committed repair view.

Rejected duplicate registration changes no existing binding or metadata view. A query or pending native call through the first valid context behaves the same whether a duplicate import is attempted or omitted. The separate live membership check handles late first registration anywhere on the retained noncanonical native route: root, intermediate identity or receiver. A newly registered identity makes continued host access fail locally. Already-started effects are not undone. Historical metadata never grants native authority. Entered queries use their private ordered metadata view. Host calls trust their canonical nodes and recheck only retained noncanonical identity dependencies.

A native mutation's published metadata distinguishes its own failure from an existing blocker and from an independent result Error. Blocked work preserves earlier state. Successful native completion followed by a result-import Error does not create scope poison. Required earlier host effects remain native-ordering dependencies even when no data value is returned. Metadata readers retain publications that can change their result; a valid repair overwrites selected-subtree poison without consuming those outcomes. Observations capture metadata without holding native exclusions for that capture's lifetime.

### Metadata publication handoff

Repair and mutating entry can leave a subtree publication pending: selection or required repair prerequisites are unresolved, or the entry callback remains open. That publication resolves to a subtree version which may contain narrower pending publications. Consumers follow only the captured own state, ancestor blockers and selected branches required by their operation. Resolving the enclosing publication does not recursively await every descendant; install any inner pending state before exposing the enclosing version.

Reuse the managed pending-container rule for later issuance in the same ordering view. A later write targeting at or below an unresolved subtree publication, whose selection or result needs that predecessor's resolved subtree, captures the predecessor and installs its own successor version at the pending node before returning. When the predecessor exposes its subtree, the successor continues from that captured version and narrows to its actual target. Each publisher settles only its own version; publishing an entry's private view cannot replace an outside successor already issued against its enclosing future. Private entry work still excludes that future.

A query captures the latest version visible at its issuance, including any earlier successor writes, without installing a publication of its own. It neither skips those writes by reading only an older predecessor's resolved subtree nor recaptures a later live view. Do not defer this capture until a managed gate opens: a later ready ancestor repair could then leak into the earlier query. Required own/ancestor blockers and selected-branch dependencies still determine when a capture can be consumed.

A reset whose selected target covers the pending node replaces that subtree once its own selection and publication prerequisites are complete. It does not chain behind the covered metadata publication or wait for an earlier repair's unresolved key merely to overwrite its result. For an external api, `api[k]!!; api!!` permits the second repair to complete while k remains pending, provided its own strict-ancestor and managed restoration/publication prerequisites are satisfied. A reset below a pending node may still need its resolved state to select the target or check strict ancestors. In particular, api[k] can select api itself through an unregistered native suffix; its unresolved repair can therefore change api's own poison. The [ordering witnesses](phase6-selection-experiments.md#ordering-witnesses) distinguish that dependency from the healthy-owner progress control. Required managed gates are not bypassed by metadata replacement. No reset awaits poison outcomes it overwrites. Earlier queries and publishers keep their captured versions; late settlement cannot repopulate the reset subtree or its summaries. Superseding a version neither discards an earlier query's required result nor cancels native work.

- When a repair key selects a narrower branch, expose the prefix version containing the selected branch's pending transition. Unrelated branches can proceed. Key delivery is not repair success: remaining keys, strict-ancestor checks, managed restoration and required preflight/publication still determine that transition. Successful repair replaces its selected metadata with empty state; failure preserves the prior state, including pending publications.
- Check a reached blocking prefix before consuming another key. Metadata repair excludes its currently selected scope's own poison but checks strict ancestors as selection narrows. Native mutation checks its fixed scope once before receiver-key selection, preserving complete required Error collection; repair-and-call excludes the subtree it can clear. An unused invalid, poisoned or pending suffix cannot replace or delay an already determined prefix failure.
- At mutating entry callback closure, publish the current private metadata view into the entry's own version with its outstanding nested publications. A transition still controlling root publication or atomic managed/metadata commit remains pending. Nested entries and issued commands retain their own work, and private captures exclude the entry's enclosing future. This handoff neither narrows the entry's fixed native coverage nor completes its contained host effects. Readonly entry retains its captured metadata view and creates no metadata mutation merely to perform observations.
- A native mutation publishes only its node's own poison outcome, not a replacement subtree. Its own failure adds scope poison; success, an existing blocker and an independent result Error preserve prior own state. Children remain untouched. A pending native own-poison outcome does not itself require descendant publications to rebase through a subtree replacement; required own/ancestor blocker checks and actual native ordering still apply. Shared version settlement updates only its captured destinations.

Successor links represent unfinished publication dependencies, not completed operation history. Chaining at the pending node must bound predecessor storage; separately verify that narrowing, copying, subscriptions and component delivery do not repeatedly traverse an avoidable N-by-N history. Use the existing operation owner and captured-publication lifetimes, clear spent captures at last use, and drain history-sized completion iteratively. Add no publication scheduler or global work registry. Native reservation completion remains separate.

### Collection and recovery

Each repairable Error belongs to its selected scope; child summaries do not duplicate it into ancestor-owned poison. Preserve original Error identities and contexts. A query blocked by a captured strict-ancestor Error returns that blocker under ordinary scope rules. At its selected scope, getErrors collects the complete required union of own and descendant poison, including when that scope itself owns poison. hasError may short-circuit. Under the [managed-poison collection rule](data-limitations.md#contextual-error-collection), a guard terminates managed-value traversal but does not suppress the selected canonical resource subtree's required Error collection. Join visible managed poison with that metadata without inspecting the hidden recovery graph; hasError may still finish on the guard. Observation-only external roots stay opaque; selected properties retain their ordinary import/query boundary.

Repair-only validates canonical selection and preflights required managed restoration before committing. Invalid keys, missing/scalar prefixes, attempted traversal through off-path aliases, readonly violations and supported preparation/publication failures preserve all prior placement, recovery and external metadata state; an invalid repair never poisons a healthy native owner. Strict-ancestor own poison still prevents reaching the target. Clear only covered repairable poison. Successful repair returns undefined; independent ordinary Error data may remain, and repair grants no host authority. A rejected context import has no recovery baseline, so repair preserves its Error rather than creating a valid context. Repair never changes host state, bindings or registration topology. Repair uses captured metadata versions and ordinary managed placement ordering; it creates no native mutation or candidate reservation. The [cutover record](phase6-selection-experiments.md#failed-repair-cutover-and-candidate-reservations) retains the migration history.

Restore a managed baseline and reset covered external metadata as one ordered completed repair. Finish fallible selection, restoration and publication preparation before committing either part; failure preserves both. The metadata reset is unconditional: healthy, poisoned and pending prior subtree state all become empty without a poison query, pending-descendant walk or wait for earlier native outcomes inside that subtree. The repair's own pending keys, strict-ancestor own poison and required managed placement/publication transitions remain genuine dependencies. repairPath retains completion/error reporting for those dependencies; it does not become an immediate issuance-only return. Earlier queries and native publishers retain old versions, so their late failure cannot repopulate the reset state. Actual native reservations remain active: later overlapping host access still waits, while independent siblings and post-repair metadata queries do not inherit that wait through repair. Later failures in the new view and unrelated branches remain visible. Ordinary managed Error data without a recovery baseline remains that Error and clears nothing behind it.

Repair-and-call performs successful repair, then ordinary call preparation and invocation with the required ordering preserved across the handoff. A dynamically selected canonical repair-only target does not authorize a dynamic native call. Preflight only the intended call's structural route, mutation scope and readonly capability before clearing; failure of those checks preserves prior state. Structural route uses consumed path/provenance and the fixed tree, not hidden baseline values. The [repair/call boundary](data-limitations.md#repair-and-call-preflight) leaves restored receiver availability and value-revealed authority to the ordinary call after repair. Method-name validation (including constructor and unsupported Array methods), receiver category/dispatch, value-revealed authority, arguments, member resolution and invocation use the ordinary call path after repair commits. A restored off-path alias or unregistered external fails there with new local poison and no host call. Their failures publish the new call poison against the repaired baseline; do not add a second early dispatch path. Failed repair returns its causal Error and suppresses invocation. Compose ordinary repair and call transitions under the source operation's original ordered ownership, rather than blindly issuing both or delaying call issuance until after a pending repair. After repair commits, a new preparation or invocation failure follows ordinary mutation rules using the repaired baseline. Live authority follows the [registration-membership rule](#registration-membership) before further host access. A rejected duplicate claim cannot prevent a valid canonical call; a later call failure cannot undo a repair that already committed. Never resurrect deliberately cleared poison or treat repair as native rollback.

The declared repair scope also selects managed recovery at a native binding. A call scoped to `api` with receiver `api.child` may restore a guarded `api` binding and clear `api` metadata; a call scoped only to `api.child` cannot restore that strict ancestor. Required fixed-tree key selection finishes inside the binding's placement transition before restoration. Once the path leaves that tree, remaining native suffix access belongs to ordinary post-repair call work. Return a failed preflight's causal Error while preserving the original guard and recovery, rather than confusing the preserved placement value with the operation result.

Canonical managed namespace poison follows authoritative placement publication through COW, entry and repair; unrelated copies cannot retarget it. A native failure has metadata poison without a managed rollback value. Keep those distinct payloads while sharing ordered capture, pending publication, failure preservation and last-use release.

## Host boundary

External methods operate on native receiver-owned state, not raw managed parents, siblings, or aliases. Observation-only external references in managed methods remain opaque: retain/compare them if permitted, but do not inspect or mutate their host state. All host arguments use the existing preparation/export and argument ownership contract; source position above or below `!` creates no additional mutation permission. There is no special ancestor-argument mode.

External calls and property writes use common guarded host boundaries and action-specific Error kinds. A native setter/reflection throw or false write/delete poisons the selected mutation scope; exporting an Error-valued RHS skips native storage and poisons that scope. Every observation Error affects only its result. Already performed native effects are not rolled back.

Method results use ordinary causal import, not implicit snapshots. Return independent managed data or relinquish mutation of it. Ready results remain available while nested Promises are pending. Fresh data receives result validation; a prepared managed reference keeps its existing value and producer after direct boundary checks. It requires neither validation copies nor another subscription to its pending properties. No ready-only result restriction or full-result await is introduced.

Prepared results preserve complete source placement state, including recovery baselines and absence. Ordinary ownership isolates later mutation or repair through a result holder. Merely returning a standalone Error transfers no recovery state, and newly created result-boundary Errors acquire no source recovery baseline.

Successful native completion and result admission have separate effects under the [method-result contract](data-limitations.md#method-results). Exact-receiver rejection, structural preparation failure, and Errors carried in result data affect only the result. They never poison a successfully completed mutation, whether discovered immediately or in independent nested data. Native method throws, rejections, and direct poison results still poison the selected scope.

Registered mutable identities confer receiver authority only through their canonical routes. Host-input export, direct property extraction and callback exposure retain their boundary restrictions. Method results may carry inert references under the [receiving contract](data-limitations.md#method-results); storing or returning them transfers no authority. Exact native receiver rejection remains a separate result check.

Registration also determines extraction behavior. If apis.db.config is registered, lookupPath of that object returns ExternalCapabilityEscape rather than a detached copy; traversal through its canonical route to config.timeout may still return the scalar value normally. An unregistered apis.db.other can be snapshotted when its data satisfies the snapshot contract. Snapshot traversal encountering a registered identity at any depth fails capability validation rather than copying its native interior. Observation failure poisons only the returned result. Managed-parent lookup may still retain an inert reference, without transferring authority.

## Managed and external ownership

Managed lookup, argument capture, import, and retained results keep ordinary sharing, leases, COW, and placement versions. Copying a parent to another owner grants no native authority. Controlled mutation scope selection consults only the canonical external tree at its route; do not scan unrelated managed data, await an unused pending alias, or maintain an identity-containment flag to reject inert references. Native managed methods consume their complete receiver and reject registered mutable identities during that existing preparation, including off-path aliases. These checks protect different boundaries: an inert reference is safe to retain as data but unsafe to give native code as an accessible receiver child.

Entry grants access ordering only. Gate installation uses ordinary ancestor COW when sharing or leases require placement isolation; an unprotected ancestor needs no copy. Entering does not eagerly deep-copy its selected value. Actual contained managed mutation decides its own COW. Source origin, Error attribution, and previously captured outputs remain unchanged through poison and repair.

## Snapshot transaction

Property reads from mutable external state hold their observation reservation through direct availability and ready-data capture. End source access and release the reservation before resolving the captured identity partition: earlier managed identity work may itself require later native access. A direct Promise may resolve before capture, but nested pending data is invalid and is not subscribed. Ready data with unresolved identity is valid; it waits only after capture, then uses canonical assembly without rereading the source. Native sources are not admitted before snapshot classification. Already-managed sources use logical property versions and Array projections, including sparse topology and native logical length. Snapshotting does not allow direct native mutation or traversal into raw managed storage by host methods.

Property-path observation may cross between native state and already-managed logical data more than once. Choose the read mechanism for each reached identity; an external-to-managed-to-external-to-managed path is valid when every access satisfies its ordinary authority and readiness rules. This grants no native call/write access to managed storage. Mutating traversal stops as soon as it would cross managed storage, so an external identity farther down the route cannot regain mutation authority. Readiness validation at intermediate native values and managed snapshot placements never invokes then or admits the source; it preserves the relevant path/snapshot Error kind. Only a final native property value has the direct-Promise availability exception.

Use existing admission or ordinary declarations/defaults to choose copy versus opaque leaf. Copy managed records, Arrays and explicitly managed class state with their supported prototypes, aliases and cycles; preserve Functions and permitted exact observation-only external leaves. This applies recursively and equally to lookup and direct export. Read fresh managed-shaped data through own enumerable data descriptors without invoking getters; retain logical captures for prepared sources. Reject registered mutable capabilities wherever encountered. Stage capture records and exact-leaf admission, collect every discoverable poison in traversable data, and discard incomplete output on failure without waiting for identity. Allocate final shells through the shared assembler and admit successful lookup output atomically; direct export remains unadmitted. Ready reflection failure receives the snapshot boundary's Error kind; internal invariant failure remains fatal. Ready snapshot inspection retains its own boundary; it feeds the common identity resolver and assembler without a generic mode-driven traversal.

Observation-only native property results use common declaration/default import and require no mutable reservation. Outbound export uses its normal complete Error collection and independent managed copies. End source reservations after required capture and processing, not after unrelated nested result availability. Exact external leaves obey the read-only host contract; a snapshot is not permission to expose a live mutable child without its resource ordering.
