# Iteration plan: sequential-equivalence review

Review date: 2026-11-19. This is evidence and review history, not a separate normative specification or certification of the unimplemented partial-layout runtime. [iterate-plan.md](../iterate-plan.md#sequential-equivalence-is-the-publication-criterion) owns publication, iteration and rollout; [Chain modes](../poison-policy-plan.md) own failure policy; the [method specification](array-method-specification.md) owns evaluator rules. Tables below summarize those sources, which take precedence. Current production contracts change only at their implementation cutovers.

## Sequential reference for success and failure

Use the same source program, inputs, captured aliases, successes and failures. Execute logical effects sequentially in issuance order with outcomes ready. Compare every observable result and effect against that reference, including intermediate reads, skipped bodies, and the data that exact repair exposes. The [numeric count cap](../iterate-plan.md#maximum-logical-count) defines the exceptional representable fallback deterministically.

For compiled loops, the [program-level reference](../iterate-plan.md#sequential-equivalence-is-the-publication-criterion) also compares which commands get issued. Supplying the oracle with the concurrent implementation's chosen commands would miss wrong branches, break/return effects or else selection.

Unordered discovery is a delivery optimization. It cannot change output order, the index of a surviving occurrence, the first/last matching index, a mutation's returned length, or cross-Chain effect order. Required dependencies may stay pending indefinitely; an implementation may not replace pending with Error, fallback, a hole, or successful exhaustion.

## Searches after actual failure

Pending success is settled: wait while survival can still resolve either way. A permanently rejected deletion-count Promise is a different state; it will never later reveal a successful count. The selected streaming fallback then contains permanent structural Error slots and has discarded the candidate C/D payloads.

In an accessible streaming Array with regional structural failure, a definite eligible match can establish `includes=true`. A negative result depends on every relevant candidate. A required actually failed selection contributes its cause and pending membership still waits. Whole-Array poison blocks access through that receiver in every mode, including short-circuit searches. Ordinary payload Error comparisons retain their separate semantics.

## Complete-mode access review

The selected contract is strict: no ordinary consumer exposes retained Array data while logically earlier work could still whole-poison that captured version. This includes unchanged prefix reads, methods, indexed writes/deletion, iterator steps and empty completion, direct method results, export and nested native preparation. The [complete access gate](../poison-policy-plan.md#complete-access-gate) owns the route inventory and query/recovery/reference exceptions.

Certify the captured predecessor, not a live flag and not every payload. Ordinary [pendingA,B] can issue element holders and expose B because payload rejection does not whole-poison the Array. An earlier pending structural operation can create a genuine whole-Array dependency even for B. Later mutations belong to successors. Private entry work must not wait on the enclosing output it is producing; an outside consumer of that output does wait while required validity is unresolved.

Complete retains current data under blocking status after failed mutation. Earlier successful producer appends stay committed internally, but their existence does not justify consuming the still-invalidatable post-producer Array. Repair exposes retained current data; complete is not a transaction rolling back the whole producer. A receiving channel preserves that captured status.

These strict-gate witnesses remain integration requirements; the prior runtime/layout probes above do not implement or certify this new access policy.

## Withdrawn proposal for access through Array poison

An earlier proposal let either streaming mode access a saved prefix after the Array itself failed. It was withdrawn. For an operation that can fail the entire captured Array, the ordered transition must exclude that outcome before the first item or any effect that could alter the data exposed after repair. An older snapshot and a healthy Array containing a failed slot still have their ordinary behavior. ## Complete-only validity clarification

Complete mode treats more structural failures as whole-Array failures. All modes derive possible failure at the applicable scope from captured transition/placement state and open issuers. Healthy arguments or zero pending commands cannot certify an open output. Required validation, comparison, publication, and a nested issuer can still matter. Ordinary payload rejection and independent result failure stay local. [Complete-mode validity](../poison-policy-plan.md#tracking-complete-mode-validity)

Complete consumption can proceed once remaining relevant failure is excluded, without waiting for unrelated payloads or all layout facts. Its first successful step therefore cannot precede a later whole-Array failure of the same captured source. Subsequent mutations belong to successor versions. Queries, repair, internal references and private producer commands preserve their existing exceptions and predecessor views.

The streaming modes preserve independently established regions around local failures. They also use Cascada's ordinary failure targets, break/return channels and scope ownership. Closing a cursor ends its unread traversal. Required body effects and terminal failure reporting retain their own obligations.

## Channel mode, break and return clarification

The user selected a per-channel constructor mode with out-of-order streaming as the default. This supersedes the earlier recommended complete default and closes the language-selection question; API spelling and compiler plumbing remain implementation work.

The user's break channel starts false and becomes true at the ordered break point, suppressing later body processing. Function return uses the same channel/conditional mechanism at every affected scope: a return inside a loop guards later body code and following code in its enclosing scopes. Neither channel write means cursor closure or completion of already-issued work. The earlier review incorrectly treated a current sequential-return shortcut as an unresolved language contract. That shortcut must preserve the user's specified ordinary control and scope dependencies; checking it is implementation work, not a new user decision. These observations do not certify the future managed-Array integration.

The [streaming failure inventory](../poison-policy-plan.md#whole-array-failure-in-streaming-modes) distinguishes unresolved regions, source-selection failure, the selected sort exception, opaque native scope, and controlled-method result boundaries. The [capacity revision](../iterate-plan.md#streaming-capacity-revision) uses logical Error positions beyond the ordinary Array limit, including loss of values remapped there. Under the user's stated tolerance for this extreme failed state, its fallback length saturates at Number.MAX_SAFE_INTEGER and later operations use that exact fallback; no lasting positional-indeterminacy state is added. Potential saturation must never add a global readiness check or delay otherwise independent work. The older streaming overflow policy is superseded in the planning contracts; the subsequent review below resolves the concat/flat, with and unrestricted length/key policies without claiming implementation.

## Full-plan design review, 2026-11-22

The captured-layout design gives the ordered cursor, searches and mutations a common source of truth. Its first useful implementation can be small. A determined-layout cursor can deliver the second binding of `[pendingA,B]` while the first binding still owns its pending payload. One pending-count splice then exercises the genuinely new machinery. General compiled-loop and streaming cutovers need the contract corrections below. These are review recommendations against kernel revision `186e39df566d` and Cascada revision `585b2d680cd7`.

### Findings affecting observable behavior

1. **Preserve Array loop metadata at the first compiled cutover.** On the same three ready items with concurrency one, Cascada's Array adapter delivered lengths `[3,3,3]` and last flags `[false,false,true]`. Its async-stream adapter delivered `undefined` and `false` throughout. A body using `if loop.last` would issue different commands. Cascada has a regression test that expects `3-F,3-F,3-T,`. Derive existing Array metadata from the captured index and shape when a body uses it. On a partial layout, a body at concurrency one must be able to obtain those facts independently of the next pull. Specify the coordinates for skipped positions too. Using the captured fallback index and length preserves the relationship to indexed reads. Keep the compiler's public pacing normalization at this same boundary. A limit of `1.5` started two Array bodies and one async-iterator body before either could finish in the current adapters. If the new window takes an integer, map the existing Array setting explicitly, including its zero/null/omitted unbounded cases, or document a language revision. [Planned metadata](../iterate-plan.md#metadata-and-value-ready-batching) · [Cascada limit-one Array test](https://github.com/geleto/cascada/blob/585b2d680cd75fc74c4beec250d39d56cca64f36/tests/pasync/loop-concurrent-limit.js#L2349)

2. **Keep missing output at the failed occurrence.** For an unordered source `[A, structuralError, B]` whose body pushes into a streaming `out`, the selected result is `[A,marker,B]` and B's push returns 3. My initial recommendation of a loop-end marker would have returned 2 and changed the order of effects. Cascada's ordered buffers already provide the proper reservation. A terminal rejection reports the remaining failure and adds no second marker. A failed conditional inside an issued body uses its own reservation. The integration checks cover a later parent append, skipped positions with a shared cause, bound one and deferred failure. [Reserved contributions](../iterate-plan.md#reserved-append-contributions-across-pipeline-stages)

3. **Make the receiving operation explicit wherever status must survive.** In the public kernel, failed mutating sort of `[2,1]` with comparator `42` left repairable status. Lookup returned the very same poison as the call. Repair exposed `[2,1]` on the source, while a Chain constructed from that lookup still contained poison after repair, exactly like a Chain explicitly initialized with the Error. The raw argument has already lost the information needed to distinguish the two cases. Route state-preserving compiler transfers directly from a captured placement into a receiving holder. Keep ordinary value extraction's existing result. A healthy hole needs one further projection when binding an item. The binding has a present `undefined` root, while a structural Array copy preserves absence. Today's placement transfer deletes an absent destination. The distinction is observable even though both value lookups yield `undefined` because method selection on an absent slot and on present `undefined` reports different Error kinds. Exercise both transfers through the compiler, including pending status and isolated repair. [Handoff requirement](../iterate-plan.md#captured-state-across-handoff) · [Chain construction](../src/chain.js) · [Placement transfer](../src/property-versions.js)

4. **Separate a length write from growth, and apply capacity before publishing point overrides.** The method rules preserve the same-length write in `a!.push()`. The original oversized-reception table and final-count rule called it a no-op. On an empty Array, both ready and deferred public executions returned 0 and exported distinct before/after identities. Preserve that specified write on ordinary Arrays. The selected rule applies the same candidate-capacity check to an inherited oversized complete receiver. Zero-argument `push()` reports capacity Error and flags the retained Array. There is a second conflict on deletion. At illustrative MAX=3, deleting index 3 of `[A,B,C,E]` cannot publish the clean absence promised by the generic deletion table while the virtual-tail policy requires structural Error at that index. Apply the ordinary edit, then the tail projection, then publish its point and identity outcomes together. Test an earlier capture, the post-delete cause, and an ordinary in-range deletion as the control. [Write contract](../docs/data-limitations.md#managed-identity) · [Deletion decision](../iterate-plan.md#deleting-inherited-uncertain-presence) · [Oversized reception](../iterate-plan.md#complete-mode-receiving-an-oversized-value) · [Virtual positions](../iterate-plan.md#virtual-positions-and-full-consumers)

5. **Use exact offset arithmetic for virtual coordinates.** For `L = Number.MAX_SAFE_INTEGER`, `s = L-2` and `i = t = 4`, the specified `s+i-t` evaluates to `s-1` in JavaScript. A one-slot `copyWithin(4,s,s+1)` can consequently copy the adjacent virtual slot's Error cause into an ordinary, readable position. Check `i >= t`, then compare `i-t` with `e-s` before adding the admitted offset to `s`. Saturate count operations only where their result may semantically saturate. In 1,850 in-range near-limit selector cases, the published expression rounded incorrectly in 195 and the difference-first expression matched the integer oracle in all 1,850. These are coordinates in the already settled, representable fallback. ### Architecture and work bounds

## Follow-up implementation decisions

The private mutation outcome loses the distinction between fresh effect failure and existing Error data before the enclosing owner publishes. Twenty-four public-kernel cases compared both a root owner and a nested owner across ready, synchronous and deferred inputs. On a fresh failing splice, a pre-repair sibling write leaked through and repair left the child flagged. On a call stopped by a receiver already containing Error data, the healthy sibling was incorrectly blocked. A receiver already carrying own status and a successful pop returning the same Error supplied the controls. The plan now carries the operation's own failure to the selected owner and keeps direct-result completion separate.
