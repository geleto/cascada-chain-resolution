### Settled decisions and rejected shortcuts

These are controls on the audit, not new defects to fix:

- First actual import preparation owns source context and derived deduplication/compound reporting; collected-poison order is currently unspecified. First encountered fatal wins immediately. Neither exception permits different values, validation policy, required causal failures or effects.
- Only explicit mutation has application-visible mutation authority. Pure reflection may follow availability; live native reads still respect writes. Do not restore the removed inspection queues, copies or waiting leases solely to enforce pure-hook order.
- Prepared results preserve producers; native mutation still validates its complete working receiver. Ordinary import cannot substitute for native finalization: a poison overlay does not make an actual callable native `then` safe.
- Import preserves healthy surroundings; export aggregates required poison. Fresh and prepared inert capability references gain no authority; capability use/export and exact-receiver restrictions retain their own boundaries. Do not restore obsolete fresh-result revalidation tests under old Error kinds.
- Receiver publication, result admission, source access, output disposal and complete poison collection have different completion points. A universal completion event, blanket preparation queue or earlier release is not a simplification unless all those obligations remain satisfied.
- Weak exact-receiver membership solves diagnostic-only retention; it does not replace strong protection for pending native access/publication. Hiding or formatting stacks, allowing spent runtime captures to leak, deep equality as identity, physical substitution, snapshot projection chains and a second lifetime framework are not selected fixes.
- Earlier suggestions that a surviving cleanup mutant proves dead code, or that every prepared container must have zero incoming placements before initialization, were not valid general proofs. Re-establish supported reachability, full state transfer and resource ownership before removing a guard.
- The proposed import-session object, generic classification wrapper, universal completion boundary and removal of the intermediate mutable snapshot were [evaluated without a retained improvement](phase4-review.md#independent-third-pass-reconciliation-2026-10-21). They are not unfinished deliverables. Revisit only with a concrete improvement over the current implementation, preserving the separate policy, collection, native-access and output lifetimes; shorter signatures alone are insufficient.

### Imported-Promise ownership

Phase 5 owns current verification of these existing constraints, principally through B01, B08, B09, B10 and B19:

- Keep one staged walk per synchronous import segment and branch-local structural poison. Authority-transaction or exact-receiver failure commits no fresh admission, origin, Promise placement, fixed imported version, tree leaf or topology. Staging needs no protection lease or topology activation. Preserve earlier independent publication and healthy branches; failed staging leaves existing owners responsible for their work.
- Synchronous supported delivery continues the active segment and identity map. Later committed delivery starts a segment at its existing FIFO position, retaining its original policy, context and failed-inspection reuse. Independent preparations may retry unadmitted failures. An abandoned segment's callbacks retain no publication authority; completed histories and failed source identities must collect.
- Keep finite occurrence-sensitive external-tree discovery separate from identity inspection and commit it atomically with admission. Original Promise availability never becomes discovery authority through later settlement or copying.
- Import owns raw subscription, fulfillment preparation and boundary policy; shared placement code owns capture, construction, producer tracking and complete prepared-state publication. Prepared results preserve their producers through copying, gates and repair; ordinary reads cannot admit unfinished staging. Reuse the existing Promise version, without an installer callback, delegation loop, second overlay store or duplicate processor.
- Verify aliases, cycles, versions, imported protection, ready reception holds, cached restoration after retirement, abandonment and failure-map release across ready/synchronous/deferred delivery. Apply the approved import source-attribution exception; it does not permit different admission, authority, poison presence or effects. Internal import joins its enclosing transition and escaping managed values retain their normal handoff.

Keep [import-processing.md](import-processing.md) aligned. No file reorganization or importer rewrite is required absent a demonstrated defect or a simpler ownership boundary. Phase 7 will reuse this matrix and its retained tests, adding the Phase 6 path interactions rather than creating another audit specification.

### Retained receiving and invocation differentials

Deterministic route-pair tests and the managed-record publication model remain necessary but do not cover randomized complete histories across receiving boundaries. Phase 5 must retain that missing coverage in `test/`, using the existing graph/identity expectations and replay helpers rather than a second framework. Scratch-only differentials do not satisfy closure.

Generate each supported program once, then replay fresh equivalent inputs with ready, synchronous, native-Promise and ordered delivery, including different independent settlement orders. Cover ordinary import, method/host results, observation-only property reception, mutable snapshots and managed/native invocation; cross shared/prepared/fresh graphs, aliases/cycles, writes, poison and required failure collection. Pair only routes whose contracts promise equivalence. Mutable snapshots' ready-only nested-data rule and root/scope query distinctions keep explicit negative controls.

## Test-evidence requirements

Past clean reviews missed defects partly because the evidence did not execute the claimed condition. Phase 5 must enforce the following before counting a run:

1. Pin production sources **and test/tool inputs**; label scratch prototypes, faulted runs, reviewer-reported results and current executed results separately. Build the final implementation with superseded paths removed; a loader bypass is not cutover acceptance. Verify hashes when reusing partition results after edits.
2. Check child/VM execution explicitly. Forward or explicitly supply required loaders to every relevant runtime worker; validate substitutions/hits with mandatory anchors/receipts and a failing no-op-loader control where substitution is used. Normalize file URLs, including Windows drive-letter case. Parent loading is not evidence of child loading. Tracer/fault hooks must compose without silently skipping bodies.
3. Keep transformed-source coverage separate or accurately mapped. Same URL/length is not a source map. An unexecuted branch needs a producer/caller investigation; do not fabricate malformed integration controls to hit it or declare it removable from zero hits alone.
4. Migrate obsolete assertions individually and execute the remainder of each test. Preserve topology, isolation, causes, ordering and recovery assertions. Tests stopped before delivery, untracked/unlaunched fixtures and stale safeguard anchors are gaps. Verify the final commit candidate includes every required file.
5. Generate programs and random inputs before replay; use equivalent input ownership and immediate managed handoff in all runs. Keep operation contexts distinct where attribution is tested. Do not let a later import repair missing admission, settle all inputs before purported pending reuse, or let observation instrumentation retain/index data invisibly. Pair observed/verified runs with bare semantic controls.
6. Compare the dimensions a generator actually models. Normalized poison markers in the publication model do not prove cause membership/source/kind; kind-only equality does not prove values, aliases or effects. Apply the narrow import/reporting exceptions explicitly, alongside separate checks that no causal failure vanished. All-ready native comparison supplements, rather than replaces, the written contract and identity oracle.
7. For every matrix row's distinct enforcement/release obligations, **including unchanged code**, cite a witnessed representative fault or a concrete reason injection is unsuitable and the alternative evidence establishing sensitivity. Map shared witnesses to the actual callers/conditions they exercise; neither one fault per file nor a registry-entry count establishes coverage. A fault must cause the intended assertion to fail; startup errors and timeouts are not detections. After one leak is fixed, retest for masking paths. Surviving mutants require explanation, stronger coverage or a supported removal argument, not automatic deletion or a new production guard.
8. Use process deadlines with startup margin for hangs/GC and external process limits for microtask starvation. Assert ready completion directly where the contract promises it, then release test gates. A required never-settling Promise is permitted; an unnecessary wait or introduced dependency cycle is a defect. An overloaded test timeout needs an isolated rerun and cannot count as either a semantic failure or a pass.
9. Use bounded continue-after-failure support in the existing generated runners for investigation. Continue only with an independent case in a fresh execution; never resume a failed execution or reuse contaminated model/input state. Isolate/restart the worker when an escaping failure or hang prevents safe continuation. Report each failing program/seed/mode and final attempted/passed/failed/skipped totals, count coverage only after assertions, and exit nonzero if any case failed. Keep ordinary fail-fast runs available; no swallowed rejection, global error sink or retained history of failure graphs is permitted. The implemented options and retained controls are described in [the test guide](../test/README.md#scaling-generated-runs).

Validate that continuation mechanism with a small scripted batch containing two independent failures separated by passing cases. Both failures must be reported, subsequent healthy cases must actually execute, counters and final exit status must be correct, and failed work must not contaminate or retain later cases. Exercise worker restart separately for an escaping failure or deadline. Reuse existing start/partition controls or a small runner where sufficient; this obligation does not require a generic worker scheduler or a new test framework. Ordinary clean closure runs still require zero failures and no unexplained skipped cases.
