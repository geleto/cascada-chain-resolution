## Questions derived from the contracts

The work bound follows explicit inputs, produced outputs, the captured Promise frontier and maintained dependencies. For a four-element current Array and at most three four-element retained readers, repeated replacement cannot justify an ever-growing current backing or an ever-growing set of obsolete logical owners. A pending `pop`/`shift` result is independently required output: its captured element remains necessary until delivery even after that element leaves the receiver. Those results must be counted separately from obsolete receiver history.

The public-value model is native sequential sparse-Array execution. Every operation maintains the four-slot logical range; a later write cannot change retained snapshots. Complete settlement must release current copy-delivery use registrations and temporary capture continuations. Once all old result Promises and setup references are discarded, later inserted-and-removed object payloads should collect; a retained earlier view must still preserve its own children.

Whole-backing retention has an explicit allowance in `docs/array-view.md`: a nonempty subview can retain physical elements outside its logical range. Shrink-only retention is therefore not reported as a leak. The rule requiring bounded discarded backing applies during subsequent growth. Sparse bounded-range enumeration also has an explicit range-scan allowance; this review does not reclassify it as a current defect.

## Source traces

`ArrayView.tryExtendEnd` serves push, concat and past-length assignment. It requires the physical tail, rejects imported storage and reserved pending tails, and falls back to ordinary materialization when the discarded offset exceeds the live length. Pop and shift derive bounds; slice uses the same derivation. Unshift and splice use placement remapping. These separate paths motivated the new combinations rather than another push/shift-only test.

`copyArrayOverlays` transfers relevant local versions; canonical backing producers project through bounds. `copyPlacement` selects the source's captured shared delivery, then installs independent destination authority. `retainCopiedDelivery` and `releaseCopiedDelivery` track active destinations and independent captures. Backing-owner retirement and delivery membership are separate facts: neither current backing size nor a zero final capture count alone proves the other bounded.

The new probes count placement capture calls, `createVersionFromPlacement` calls, `copyPlacement` calls, overlay entries visited by `copyArrayOverlays`, then subscriptions, live captured continuations, and active/peak copied-delivery uses separately. These are named mechanism measurements, not a total runtime-work or total-allocation oracle. Current backing length and registered backing-owner counts are sampled after each issued iteration.
