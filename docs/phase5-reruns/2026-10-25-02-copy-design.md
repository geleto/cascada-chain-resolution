# Pending-copy and Array history correction

Status: implementation complete; validation is recorded in the [correction report](2026-10-25-02.md). The user authorized fixes for the actionable findings in the [Claude review](2026-10-25-01.md). The starting execution-input pin is unchanged from [2026-10-24 run 01](2026-10-24-01-initial.json): `bb57d772e6ca9eb76dac5ff96ddeba3b79502b4a041a546e10f9bc838f538ca8`, revision `a343e41cb023d385f8bc1980ec201764c2612b84`. Earlier successful runs remain historical; B22 and affected validation were reopened.

## Confirmed causes

- F1: `copyPlacement` and remap `placeEntry` call `transferPlacement`, which creates a fresh version and subscribes through `continueCapturedPromiseVersion`. Retiring the old owner clears its publication destination but cannot remove its native Promise reactions or the captured producer chain needed by later copies. Repeated record COW has the same mechanism. Clearing the snapshot holder does not eliminate those reactions. At N=64/128/256 the record probe retained approximately 9/32/124 MB before settlement; unshift retained 8.7/31.5/122.8 MB. The matching push control retained approximately 1/1.3/2 MB.
- F2: mutation-mode fill and copyWithin always construct a whole-receiver remap, even for a one-slot range. Their ordinary scope baseline must survive supported failure, so replacing this with raw in-place writes would violate rollback and retained-output isolation.
- F3: end extension reuses a backing whose inactive prefix grows on each push/shift pair. All 100 sampled removed objects remained reachable after 1,000 iterations although logical length was four. Existing ordinary materialization can bound this without writing or compacting retired host storage.

## F1 decision and implementation

The user explicitly approved **"Implement and validate shared captured delivery"** on 2026-10-25. That authorizes replacing the mandatory per-copy subscription mechanism while preserving ordering, isolation, rollback and Error contracts. The following paragraphs record the original decision boundary; they are not a pending permission request.

Before this decision, AGENTS.md required: "A copied actually pending Promise placement gets a fresh Promise version at the copier's program position." Promise Continuations also prohibited subscribing once for all consumers or installing another subscriber queue. These rules protect ordering between captured reads, earlier mutations, copying and later mutations.

For N growing snapshots with N pending inputs, applying that rule literally creates a triangular number of subscriptions. Native Promise reactions cannot be unregistered. Clearing their payloads can reduce the constant but cannot make the retained reaction count linear. Reusing a version merely because its destination retired is also insufficient: an earlier capture or queued writer may still own its publication, and the COW example retires its holder after the copy has already subscribed.

The proposed bounded experiment is to separate shared, captured pending delivery from independently mutable placement authority. Representation copies would retain a shared delivery capture instead of eagerly creating another delivery subscription. Actual reads and writes would retain their required FIFO positions; writes would split placement authority, and captured transitions/recovery would remain tied to the version selected when the copy was issued. This is a proposed replacement for the fresh-version-on-every-copy mechanism, not permission to share mutable versions or add an execution-wide Promise registry/queue.

The unresolved proof obligation is preservation of program-position capture through pending writers. Existing gate installation can update a captured version in place, so adding shared pointers alone is unsafe. The experiment must account for those writers centrally before replacing the current rule. A successful experiment may change the mechanism wording while preserving sequential equivalence, Error attribution, availability and owner isolation. If those observables cannot be preserved, a separate semantic decision is required; this document does not authorize one.

Required worked histories and regressions:

1. Copy a pending placement, then mutate the original after delivery: the copy preserves its earlier value.
2. Issue a nested mutation, copy while it is pending, then issue another mutation: the copy includes the first effect and excludes the second.
3. Retain two copies, mutate either one, release the other, and settle in both native and ordered modes: values, aliases and exact failures match the all-ready execution.
4. Retire and re-enter an imported cached graph while a copy survives: forward producer state remains authoritative; reverse/index/destination facts are restored only for live uses.
5. Reject or fail publication with a retained recovery baseline: all required errors and repair behavior survive; no detached destination is resurrected.
6. Repeat remapping and record/Array COW with holders explicitly cleared. Count live dependency/capture/reaction state at N/2N/4N before settlement and after partial/final settlement. Requested retained full outputs are separate controls. Aggregate element movement for unshift is distinct from unnecessary retained subscription history.

The alternative is to keep mandatory per-copy subscriptions and explicitly accept quadratic pending-copy reaction retention. That would revise the work-bound expectation rather than fix the finding, and is not recommended. A smaller cleanup that only reduces bytes per reaction does not close F1.

The implementation keeps a new destination version for each representation copy, with a shared delivery capture selected from its source version. Copies of copies reuse that capture. The first capture subscribes through the existing ordered continuation; actual reads and writes still use their own continuations. Current destinations and independently captured versions register for synchronous publication. Replacement and retirement remove obsolete registrations. Inactive forward versions retain the shared result and adopt it without host inspection or resubscription when restored. Semantic commits invalidate the source's copy cache; later writers retain independent version authority.

The deterministic 16/32/64-input probe now covers unshift, splice, reverse, fill, record COW and Array COW under native and ordered delivery, including partial settlement. At 64 inputs, unshift retains 63 captures and record COW 128, compared with 2,016 and 2,144 before the fix. Current and peak publication registrations are counted too; completed captures and registrations must reach zero. The independent 256-input heap probes dropped from approximately 123 MB to 3.05 MB for unshift and from 124 MB to 3.5 MB for record COW. Heap figures are diagnostics; deterministic counters enforce the work bound.

## Array range and backing corrections

F3 can refuse end reuse when an offset prefix exceeds the current live range, using the existing materialization fallback during the next actual growth operation. This gives amortized copying proportional to the queue's live range, leaves retained views unchanged, and keeps retirement metadata-only. Validate ready/pending payloads, holes, indexed and unindexed graphs, retained views, rejection/repair, and actual collection of removed payloads.

F2 now builds a remap of the selected range. An exclusive, writable representation with no owner-local overlays preserves its complete pre-call value in an ArrayView: the changed range is captured as overlays, while unchanged backing remains shared. The operation transfers its baseline lease to this snapshot before the first write. Failure publishes that preserved baseline through existing recovery; no inverse storage writes or undo log are used. Shared/imported storage, local overlays, constrained storage and displaced receiver gates use ordinary private materialization. These fallbacks preserve the current representation's isolation requirements; they are not a claim of range-only cost for every protected snapshot history.

Overlapping copyWithin sources are captured before any destination changes. Sparse write-identity contributions use the same collector as reverse. Source and destination presence, payload availability and record publication keep their existing rules. Point fill/copyWithin on exclusive ready Arrays now require respectively 5/6 placement captures per operation at N=64/128/256, instead of approximately 2N. New tests force failure after an earlier successful range write and at parent publication, with sparse holes, aliases and optional indexes. The sparse-remap test now retains its source through an explicit Chain, replacing an incidental assertion about an unheld runtime-owned physical Array.

The new range-failure lifetime fixture also exposed a spent storage-preparation record retained as the receiver of `storage.commit()` in a fresh Error's lazy stack. Its descriptor retained the old Array after the recovery placement was cleared. A heap retaining path confirmed `PoisonError -> cause -> CallSiteInfo receiver -> descriptor.value -> Array`. The common property commit now invokes the closure without that record as its receiver. The fixture retains unformatted fresh/prebuilt poisons from reflection, partial storage writes and parent publication, with indexed/unindexed cases and healthy live/discarded controls; all 28 cases pass at stack limit 1,000. The default wrapper also requires limits 10 and 50, and a separate safeguard restores the retaining method call.

A subsequent source review found that an in-place range result also needs the existing `IdentityPublication` transition. Previously, fresh remap output supplied a new identity implicitly. The new regression captures an Array identity in a pending search, performs fill/copyWithin without a second owner, then delivers the updated Array to the search. Effective writes must compare unequal even if their values are unchanged; empty ranges compare equal. The regression failed before the correction. The common Array result path now publishes reused receiver identity through `IdentityPublication`, preserving the baseline snapshot's earlier token. A separate removal fault and 72 cases (each indexed and unindexed) cover all three searches, owned/view storage, and native/ordered delivery.
