## Flat snapshot identities and shared access (2026-10-22)

**Historical prototype outcome; superseded by the production correction above.** This investigation evaluated one common managed access interface rather than separate snapshot Array algorithms. The flat-identity prototype removed the snapshot completion barrier without changing Array methods and superseded the rejected representations below. At that point the production tree still failed eleven strict completion checks. The adopted production design is recorded [above](#managed-snapshot-completion-2026-10-22); the public iterator remains deferred.

### Separate freshness from unfinished mutation

An identity is a pair `(domain, mutation cell)`. The domain determines which identities can ever be equal; the cell is the existing pending/settled/forward state. A mutation reserves a new cell in the same domain. A snapshot gives each incoming domain a fresh domain and shares its captured cells. Thus aliases within the snapshot follow the captured decisions, while the snapshot stays distinct from the source and other snapshots. Recapture replaces domains instead of stacking projections. One fresh domain for an entire capture would be wrong: two older snapshots can share cells but must remain distinct when copied together.

This prototype has no projected state, persistent interning table, background copy-completion work, or new subscription lifetime. Comparison checks domains before cell representatives. Complete native assembly groups by the pair. Managed snapshots can publish ordinary managed shells before that final partition; existing paths, Array algorithms, mutation, ownership and later export consume them normally. Native export and native receiver assembly still wait for canonical aliases. Required snapshot validation and reservation release are unchanged.

One alternative was tested and rejected first. Eagerly copying a finite partition into ordinary pending cells fixes quadratic history traversal, but creates source subscriptions for copies that a short-circuit result discards. After 64, 128 and 256 completed `includes(7)` calls, it leaves respectively 64, 128 and 256 subscriptions behind the same unrelated pending source identity. Flat domains leave **zero** in every case. Adding cancellation/refcount machinery to the eager scheme would add a lifetime problem the flat representation avoids.

The flat prototype's mixed snapshot/unfinished-mutation history has the following measured cost. This counter includes cell-root calls and forwarding edges, unlike the projection-only edge counter below; the figures establish scaling rather than a cross-prototype instruction-count comparison.

| History length | Snapshot construction | Final consumption setup | Identity completion |
| --- | ---: | ---: | ---: |
| 64 | 192 | 7 | 778 |
| 128 | 384 | 7 | 1,546 |
| 256 | 768 | 7 | 3,082 |

The remaining histories are actual mutation-cell forwarding, handled by the existing union/find and notification machinery. Snapshot construction adds no history edge. The representation costs one extra small identity wrapper when an identity is allocated; it adds no application-data copy beyond the snapshot's required detached data. No global canonical-key registry is needed: assembly groups representatives locally.

### Access and cursor experiment

The smallest useful interface separates **position selection** from **value delivery**. A cursor supplies keys; `read(key, accept)` uses the existing placement/version receiving boundary. An ordered consumer awaits its current read/comparison; an independent pure consumer starts further reads while earlier values wait. An all-elements consumer adds a completion condition, not another cursor kind. `at` uses one direct read. Placement remaps still transfer versions rather than unnecessarily resolving payloads. This does not require Array method scheduling flags, a new scheduler, or captured-value adapters throughout the runtime.

The access prototype passes twenty traced scenarios covering records and Arrays, ready/synchronous/native/ordered delivery, both processing orders, later writes, holes versus explicit `undefined`, direct object selection with pending children, and pending Array growth. The same probes pass with the flat snapshot loader. The source lease, exact captured versions and operation owner keep their separate existing responsibilities; these probes do not establish full iterator lifetime acceptance.

A further ordered-record probe caught a real design trap: entering `a` in `{a:1,b:2}`, then deleting/recreating it, must yield `b,a`. Capturing the old key list and only waiting for each value incorrectly yields `a,b`. The corrected prototype seals pending key transitions and sorts its key frame once, independently of payload readiness. This conservative implementation passes the probe but does not establish maximal stable-prefix progress for records with unfinished structural transitions. That progress requirement and the final public signature remain part of iterator design. Compiler integration must also prove effect order for loop bodies; a callback invoked in value-settlement order is not a sufficient interface for issuing mutations.

## Failure diagnostics and context discovery (2026-10-21)

The subsequent GPT Sol review reproduced two defects despite the preceding full-suite acceptance: lazy Error stacks retained abandoned inspection inputs, and native context discovery repeated classification that had already failed during ordinary preparation. Both are corrected in production.

- **Lifetime correction:** native discovery, prototype classification, snapshot prototype inspection and declaration boundaries clear their captured source/prototype/constructor bindings in `finally`. Declaration walks also clear their visited, staged-declaration and prototype sets. Exact causes and unformatted diagnostics are preserved; no stack formatting, weakened cause retention, new owner or cleanup registry is introduced.
- **Failure reuse:** discovery uses the preparation's existing weak failure map at its classification step. Successful category facts remain staged when later container inspection fails, so discovery can still stop at managed storage; those failed containers are excluded from admission commit. Structural child poison remains local, while required authority failure abandons the context segment atomically.
- **Adjacent shortcut corrected:** admission had also bypassed the native direct-availability check. With a failing `then` descriptor, a ready ordinary alias could preserve the context while the equivalent pending alias caused root poison. An accessor returning a non-callable value could similarly change registration depending on prior admission. Each requested native crossing now checks descriptor-based availability first, then reuses classification. This preserves availability-diagnostic precedence without reclassification, subscriptions, another cache, or dependence on alias arrival. Availability inspection and category classification answer different questions; their individual reflection calls are not conflated into one cache entry.

## Review method

The earlier review relied too much on aggregate passes and the immediately changed functions. Its lifetime witnesses did not cover the complete call stack or all neighboring callers. The replacement method is an obligation ledger:

1. **Freeze the candidate and expectations.** Use complete source files after deletions, with individually reviewed contract migrations. Record the source revision or hashes and exact commands. Distinguish production, prototype, instrumented execution and reported evidence. A test stopped by its first obsolete assertion contributes no evidence for its remaining body.
2. **Trace in both directions.** For every skip/reuse decision, identify its authoritative fact and all writers, transfers and invalidation rules. From each producer, follow publication, retained holders, consumers, failure and release. Include unchanged code. A writer being correct on success says nothing about its failure path.
3. **Cross the relevant states explicitly.** Derive cases from catalogues of public operations, internal managed/external/snapshot routes, resources (including constructors, routes, tree nodes and registry links), and exits, rather than from the diff. Cover ready, synchronous custom delivery, native/deferred ordered delivery, fulfillment, rejection, supported reflection failure, publication failure/fallback, local closure, discarded construction and fatal resumption. Cross these with root/wrapper/late reference, fresh/prepared/admitted-but-unprepared data, representation, aliasing, retained earlier views, and unresolved independent work. Use small required combinations per obligation rather than an unreviewable Cartesian product.
4. **Give each resource a last-use proof.** List what owns it while pending, what operation transfers that responsibility, and which synchronous transition removes the former reference. Separate input capture, native use, publication, recovery, required Error collection and result delivery. Trace ordinary closure references as well as metadata/leases. Clearing a binding does not clear a still-required placement or baseline.
5. **Challenge the test oracle.** Compare values, aliases, ordering, Error membership/source and recovery with independent expectations. Verify sources remain live before last use, and release actual holders before requiring retirement. Keep unformatted Errors; test prebuilt and fresh causes at default, 50 and deeper stack limits. Distinguish exact native CallSite receivers and returned/published data from runtime leaks. In heap analysis, WeakMap ephemeron edges alone are not strong retaining paths.
6. **Require falsification evidence.** Remove each distinct prerequisite or release and require a named witness to fail for the intended reason. Surviving mutants mean an untested obligation or a possible simplification requiring proof. Zero branch hits prove neither unreachability nor redundancy. Shared symptoms may have several independent retaining paths; remove each path separately.
7. **Close the ledger, not just the suite.** Each row needs a source argument, applicable timing/exit cases, tests that exercise them, and fault evidence for changed enforcement. Report gaps explicitly. Promote strict witnesses and faults when implementing; do not convert expected production failures into passing assertions. Rerun affected rows after changes, then the normal/traced suite and extended histories before acceptance.

Derive the representation and method catalogues independently too. Sampling one Array method does not cover the others' capture, conversion, traversal or terminal paths. Assert that the method catalogue covers the runtime dispatch table, but derive expected semantics from the contract/native reference, not the runtime's dispatch flags. Count actual reflection and suspension hits. Track generated native copies as well as original sources. Run the safeguard registry itself: a passing ordinary suite does not detect stale fault definitions. After finding a retaining path, remove it and trace again; a second path can mask otherwise-correct cleanup.

Subprocess fixtures must use their real prerequisites. For example, `construction-retention.js` requires `--import ./test/trace-runtime.js`; without it, its copy-count assertion fails before testing retention. Verify each child's status and required instrumentation receipt. Source-reading VM fixtures must consume the actual candidate files. Use parent timeouts with startup margin; never infer semantic failure from a heavily loaded two-second test, or kill unrelated processes.

Instrumentation must also compose. With the tracer inherited by children, ten internal-stage tests and the ownership-work test initially stopped at missing source anchors: the tracer had renamed their target functions. The candidate fault/counter hooks now target the actual renamed bodies when tracing, retaining their mandatory anchor assertions. Both instrumented and ordinary tests must run; a hook-startup failure supplies no semantic evidence.

#### Attribution investigation: 2026-10-19

A native Error carries no Cascada operation context or failure kind. First preparation creates its immutable contextual wrapper in a logical placement; later consumers of that prepared container preserve it. The witness confirms that two ordinary imports also disagree on source attribution when discovery is delayed, even though both use `ContextValueFailed`. Unifying kinds alone therefore does not solve the issue. Already contextualized Errors preserve their exact wrapper under both schedules.

**User decision: attribution must follow operation issuance order.** The previous recommendation to accept whichever preparation executes first is rejected. Waiting is permitted when needed to establish the correct attribution, even if its Promise never settles. No mandatory timeout or completion guarantee is required. The strict witness now allows asynchronous Error observation and resolves the earlier input before awaiting it; its old synchronous-observation and never-settling progress expectations are removed. It still fails the kind/source comparison on current production.

There is an information constraint, but it establishes a need to wait rather than permission to choose a different source. While the earlier Promise is unresolved, the later import cannot know whether it will reveal `inner` or unrelated data. The later Error must not become observable with a provisional source/kind. Discovery alone does not establish the winning preparation: its admission must also be final. The [commit-frontier experiment](#ordered-admission-feasibility-2026-10-20) shows that a failing sibling can invalidate that admission under the current whole-segment rule. Once the earliest applicable preparation is established, genuinely unrelated work need not delay attribution. Otherwise a later candidate becomes eligible after earlier potential preparers have been ruled out. Existing contextualized Errors are already final and retain their original attribution.

| Alternative | Assessment |
| --- | --- |
| Delay contextual Error delivery until earlier discovery permits a final choice | The required direction. A necessary discovery wait may remain pending indefinitely. Finish as soon as the earliest applicable source is known, without waiting for unrelated native work, publication, or later candidates. |
| Serialize all fresh preparation behind the oldest unfinished discovery | A simple reference design, but too broad as a default: it also blocks ready clean data. A finite host program can import `{ ok: 1 }` and use that ready result to fulfill an earlier pending input; a blanket preparation queue introduces a self-wait. This is distinct from an input Promise that simply never settles. |
| Give each receiving boundary its own graph/Error view | Can make attribution boundary-local, but changes shared identity or propagation semantics and restores validation views/copies and their lifetime machinery. Reject for this design. |
| Use producer-provided or context-free Errors | Pre-contextualized input already works. Making it mandatory moves an obligation to callers; context-free wrapping loses the causal source and boundary-specific kind. Either changes the diagnostic contract. |
| Assign attribution at the first actual preparation | Rejected by the user: source and kind must not depend on settlement or callback order. |

Three designs remain distinct. Keeping availability-sized transactions preserves the defect. ### Identity: what must actually be preserved

The earlier `isOriginal(value) { return value === this.child }` argument was too broad. Managed data already crosses native boundaries as detached copies; native code cannot depend on its original storage address. Application/entity IDs are separate from the kernel's write-based logical identity. Within one export, unchanged representations of one logical identity must share one output object; separate exports need not reuse an address.

Production probes confirm all three distinctions: an observation-method receiver copy and its source share one exported object; that object differs from the original host address; a same-value write produces deeply equal but distinct exported objects, as do independently created equal records. `captured-identity.js` records identity history, and `captured-graph.js` assembles the resulting partition. Deep equality cannot reconstruct that history.

Exact identity still matters for opaque external resources and their native state. An explicitly external object is not made safely copyable merely by having a record-shaped surface. The unresolved problem is the implicit external classification of a record obtained through an external parent, competing with normal managed admission. It is not conflicting explicit declarations.

### A feasible branch-poison design

Ordinary import must preserve healthy surroundings and existing poison. Export still collects required poison and returns poison instead of a partially exported graph. A ready child inspection problem must not discard siblings merely because they shared its preparation segment.

The isolated prototype changes the preparation unit:

1. Capture each container's keys and immediate placements before descending. If its keys/shape cannot be obtained, return poison for that container before traversing cycles.
2. If a known key's descriptor cannot be read, install a fixed logical poison version at that key and continue capturing other keys. Preserve the distinction between a successful source capture and an unreadable placement; do not invent a mutation recovery baseline.
3. Commit valid containers and their complete parent relationships. Existing poison and pending deliveries remain ordinary placement values/obligations. A successfully prepared container is reused; failed whole-container inspection is not permanently cached as successful admission.
4. Context-tree construction uses the original placement facts already captured for that segment. A poisoned property cannot accidentally grant authority, and avoiding a second read prevents tree construction from repeating the same descriptor poison and aborting the healthy graph. Actual authority construction remains a transactional boundary.

This uses existing fixed versions, construction publication and ownership. It introduces neither a boundary-wide poison replacement, a poison history, nor waiting for the complete Promise graph. The earlier local prototype failed to install an authoritative overlay for an unreadable descriptor; replacing an entire partly readable container also discarded its other poison. The new prototype avoids both mistakes.
