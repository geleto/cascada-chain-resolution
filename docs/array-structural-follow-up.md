## 2. Share the numeric decisions of an open splice

`spliceCut` starts from the predecessor width and start. Both `captureRemoved` and the independent point path also consume the count, including when it arrives first. Trace both orders through those callers. Put each repeated numeric bound at the splice that issued it. In the healthy, supplied-count case, the raw count can narrow candidates immediately. The effective deletion clips that count to the space after the normalized start. Preserve that distinction, omitted counts, failed controls and an open predecessor. Feed those facts into the existing point, range and occurrence consumers at the transition where each fact becomes available. Keep payload protection and release with each holder. Delete the superseded arithmetic and any redundant subscription it served. For each admissible healthy predecessor length N and normalized start S, the removed old positions are exactly `[S,S+D)`, where `D = min(max(count,0), N-S)` for a supplied normalized count. The successor uses the old positions on either side of that same interval, in order, with the insertion between them. Check that each refinement preserves every still-possible partition. Include failures and the Complete gate separately when deciding whether to deliver an early result.

Check start-first, count-first and issuer-first delivery. On `[A,B,C]`, issue `splice!(2,p)` followed by `toSpliced(s,k).at(-1)`. With `s = 1` and `k = 3`, both streams owe A while `p` is held. Complete still owes its gate. Also keep the open-append case where a count clips against a growing predecessor. On Unordered `[A,B].toSpliced(s,k,X)`, once `k = 1`, a lone point at index 1 can release A while `s` stays open. A live full snapshot can still return A. Preserve the fixed-layout path and existing width, point-work and collection bounds. ## 3. Share the pending copy destination window

Compute that intersection and emptiness in one place. Check the point and skip callers for the same decision. A range can prove it is entirely unchanged. An Error query can inspect an unchanged prefix or suffix immediately. Preserve both answers. Use the existing source-index and fixed-write logic.
