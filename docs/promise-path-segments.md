# Promise-Valued Path Segments Architecture

Developer-facing path restrictions are centralized in [`data-limitations.md`](data-limitations.md). This document owns the segment-consumption, route-extension and selection-protection protocol. The Phase 6 plan records implementation order, experiments and acceptance; external ordering and entry retain their own boundary contracts rather than separate versions of this path protocol.

## Model

A path segment is a String or Number operation input. Consume availability and propagate language poison before validating a successful key. A PoisonedValue delivers its contained Error through ordinary rejection; a raw rejection is contextualized at the path-input boundary. A successfully supplied native Error is invalid key data, not a rejection. Normalize each valid key once; other successful values produce InvalidPathSegment without coercion, and a Promise-valued segment must never be stringified as a Promise object.

The path carries each actual input value plus one trusted compiler fact: the first declared dynamic-segment position. A ready computed key remains dynamic. During the existing routing/consumption walk, a non-String/Number input also ends the static prefix before normalization or subscription. Thus a Promise key is dynamic even when provenance is omitted or declares a later boundary; synchronous fulfillment cannot grant static authority. Narrow the existing route fact rather than retaining a second provenance record. This type check performs no coercion, then lookup or subscription, does not report invalid unused input, and requires no scan of an unreached suffix. Consume and validate the input only when ordinary traversal reaches it. Preserve the narrowed provenance through path capture, composition and entered contexts; never infer greater static authority from a normalized String/Number key.

Public APIs carry this source fact as the final optional `firstDynamicSegment` argument, or within `run` facts; its default is `path.length`. This declares a fully static path only when its key inputs are Strings or Numbers. A valid path's effective boundary is the earlier of that declaration and its first Promise-key position, established lazily within the existing walk. Runtime entry capture and entered Chains preserve the narrowed boundary when rebasing paths, including a dynamic segment inside a retained suffix. Promise-valued key consumption and replacement of the current broad computed-failure fallback remain [Phase 6](runtime-evolution-plan.md#phase-6-support-promise-valued-path-segments) work. Local failure, computed canonical metadata access, versioned external Error views and uniform repair preservation are approved Phase 6 architecture, not current runtime behavior.

That phase also integrates write-based identity with prefix gates: capture the exposed prefix generation before waiting, extend command attribution as later segments become known, and keep outcomes pending while issued work can still publish. Search/export captures between gate installation and target selection must preserve their ordered alias meaning. An unused suffix is not consumed merely to classify an empty entry as nonpublishing; private entry comparisons never await the entry's own future closure.

Reuse the ordinary pending-placement transition for pending keys. An observation retains the longest resolved managed prefix before waiting. A mutation gates the placement holding the current managed container, or an already-selected broader mutation scope; it needs no separate step-down state machine. When a key resolves, install any required inner gate before publishing the outer selection gate; later unrelated siblings can then proceed. A selected broader scope retains its ordinary rollback and publication protection. Registered descendants do not widen the managed guard to a static fallback. The guard's placement does not itself select a semantic mutation scope.

## Preparation

Observation and mutation keep their existing walkers because mutation additionally owns COW, writeback, gating, and failure publication. Use one operation-local segment-consumption and route-extension protocol across these walkers, ExternalAccess native traversal/receiver/property selection, canonical metadata selection and snapshot traversal when it continues into managed data. Canonical metadata queries and repair use that cursor and their captured metadata without constructing ExternalAccess or retaining a native validation adapter. Entry reference capture is non-consuming and keeps its fixed anchor; actual contained commands consume its retained suffix.

Consume a key only when reached, store the normalized String in the operation's private path state, and advance its canonical tree trace at that same position. Preserve the declared dynamic restriction and any earlier type-derived cutoff, with absolute offsets through rebased and sliced paths. Every authority check, mixed-scope validation, repair target, Array namespace truncation check and registered-location replacement check must use this consumed path state. Unknown keys cannot be treated as proof that a route is off-tree. Extend the trace incrementally without rescanning consumed prefixes or consuming an unused suffix; discovering a registered node through a computed key permits canonical metadata-only selection but creates a forbidden-route outcome for native access. No computed key grants host authority or creates a registration. The caller's path array is unchanged.

Establish issuance-time external coverage from the source-static prefix. That initial routing and subsequent key consumption share one operation-local route state; do not keep a separate full-path prediction of dynamic routing alongside the incremental trace. Ready computed keys advance that same trace synchronously. Derive forbidden-route outcomes when the consuming walk reaches the registered location, preserving ordinary failure scope and existing earlier-poison precedence.

Walk ready leading segments synchronously. Consume a possible custom thenable through the common helper and continue traversal in its callback. A synchronous delivery extends the same resolved prefix. Once traversal selects the target, readiness belongs to the target operation: its independent pending result adds no prefix protection. Only a returned pending chain for unfinished consuming selection acquires pending prefix protection before the issuing stack returns. Entry instead establishes its own protection before its callback. The protection responsibilities are:

| Operation | Managed protection | External coverage and handoff |
| --- | --- | --- |
| Lookup, expression extraction, export, or receiver selection | Lease the reached prefix; later managed mutation uses COW. | No subtree reservation merely because the value contains registered descendants. An actually selected static external owner keeps its ordinary boundary coverage. |
| Contextual hasError/getErrors query | The same prefix lease and captured versions. | Capture the ordered metadata view at issuance; consume only the selected canonical branch, including a computed registered target. Add no host reservation for metadata. Preserve earlier pending outcomes and exclude later poison and repair. |
| Ordinary managed mutation | Gate the reached managed prefix or already-selected broader scope and continue against private state. Install required inner protection before publishing an outer selection gate. | Use the managed gate and preserved external frontiers without a covering external effect for work that consumes no external metadata. Verify the handoff without reacquiring behind later work or retaining unrelated siblings. |
| Repair | Use the ordinary managed selection gate and recovery transition; failed selection/preflight/publication preserves all prior state. | Publish an unconditional empty metadata subtree together with managed recovery, without waiting for poison it overwrites. Selection and required publication retain their completion/Error result. A computed canonical registered target is valid. Preserve canonical bindings; metadata repair grants no host authority and takes no native reservation of its own. |
| Mutable entry | Gate a managed anchor through ordinary placement capture; an external anchor uses its reservation alone. | Reserve the fixed anchor's covered subtree exclusively. Key delivery does not narrow the entry. Its private metadata view excludes its enclosing future; required managed, metadata and native work retain their respective completion lifetimes. |
| Readonly entry | Lease a ready fixed managed anchor or retain its captured pending version. | Reserve observation access to the anchor's covered subtree. Retain its fixed native coverage and captured managed/metadata view; readonly capability forbids repair. |

Observation-only external identities need no mutable-resource reservation. A managed lease preserves managed values; a metadata capture separately preserves the ordered external Error view. A query issued through a pending key must exclude a later failure in its selected resource and preserve earlier poison across later repair. A rejected duplicate context changes neither its captured view nor the original binding. Capture without enumerating candidate children and collect only the eventually selected metadata. Selecting a branch with no external metadata introduces no unrelated native prerequisite. A forbidden host selection consumes only its static-prefix validation metadata; a canonical metadata-only query is permitted to select the registered target.

The consuming-path handoff remains a required [Phase 6 ordering checkpoint](runtime-evolution-plan.md#required-ordering-experiment). The selected architecture uses [versioned external metadata](external-context-ordering.md#poison-and-repair), ordinary managed publication and existing native reservations. Share the capture/publication pattern without forcing resource metadata into managed property storage. Static query and unconditional repair reset must prove the transition before unresolved metadata selection is added. Use the common [metadata handoff](external-context-ordering.md#metadata-publication-handoff): install selected inner state before exposing a prefix version containing narrower pending publications. Later writes that need a broad pending subtree's resolved state install ordered successor versions at that node and narrow from their captured predecessor; a valid reset covering the pending node replaces it once its own prerequisites finish, without that metadata dependency; queries capture the latest visible version without creating a publication or recapturing after a managed-gate wait. Native outcomes update only their node's own poison and leave children untouched. Key selection can release unrelated metadata branches without completing the selected repair; a mutating entry similarly publishes its private view at callback closure without completing contained native effects. Fixed-anchor entry retains its scope: contained commands may query or repair registered metadata dynamically, while native access still requires static authority.

Preserve true dependencies while releasing unrelated sibling progress. Native mutations that subsumed earlier frontier entries retain their predecessor waits. A finished read reservation completes immediately after its own required host access and effect work finish, with any remaining work using already captured state: it removed no predecessors, which remain represented directly or through a replacing mutation for existing and future waiters. Entry completion still retains its required contained effects. No selection groups, cancellation or conditional-release protocol is needed. Versioned metadata does not justify reacquisition behind later work or loss of earlier effects. If the selected implementation becomes complex, present the reduced case for discussion before adding another mechanism.

Consume each later segment through the common Promise and Error preparation only when traversal reaches it. A direct returned result continues the current transition; pending selection resumes from the private protected value and may hand protection to a deeper placement without selecting an additional semantic scope. Record target handoff immediately before invoking the selected operation. Reuse the existing `pathSelectionComplete` fact or derive it from retained target/continuation state when that state has exactly the same meaning; do not add duplicate flags. Do not infer selection completion from callback execution or result readiness. For example, a ready custom key selecting an Array whose `pop()` removes a pending element completes traversal and receiver publication immediately; only the removed element's independent result waits, and no prefix gate or lease is added.

Initialize callback-visible staging, captured versions, and enclosing writeback required regardless of readiness before subscribing: a callback may run inside `then`. Pending-only gates, Promise versions, leases, and registrations are installed only after the returned transition proves that their dependency remains pending. JavaScript run-to-completion prevents asynchronous delivery from interleaving before that installation and the issuing stack returns. Several pending observation segments reuse one prefix lease. Reuse the pending-child placement version, writeback and IdentityPublication transitions for mutation selection: publish an outer selection gate only after the inner pending transition is installed in its working value, with enclosing writeback and identity attribution preserved. The direct operation still retains required inner publication; releasing outer protection does not complete it. After outer publication, inner work may settle only its captured destinations: it must not replay ancestor reconstruction, overwrite later siblings, or publish a new failure into the released ancestor. Finish fallible ancestor work before release or retain its required protection, including structural ownership. Settling a detached inner version cannot republish an obsolete parent. An already-selected broader scope stays protected through its ordinary publication. Never wait for unused segments or extend protection for an independent result.

If the known prefix already fails, return or publish the ordinary path Error without waiting for unused segments. If segment preparation fails, an observation returns that Error. Mutation uses the ordinary semantic failure scope: after reaching the selected scope, poison belongs there; a broken prefix before that scope follows the normal failed-placement rule. A coarser selection gate supplies publication, not a wider Error location. For example, after the first key in `P[k1]![k2]` selects a child, failure of `k2` belongs to that child even if selection initially gated P. Failed repair selection preserves existing placement and recovery state. Forbidden external routing uses the same local failure rule below; a statically selected external owner keeps its existing scope transition.

An unused segment Promise remains host-owned. Cascada does not wait for it or attach a rejection observer merely to suppress host-level unhandled-rejection reporting.

Initial mutation-tree discovery filters the compiler's finite tree of static access prefixes, with `{}` endpoints. It follows only named original placements, records requested external scopes including nested native nodes, and removes non-external endpoints and empty branches. An endpoint at a managed `!` scope does not request descendant discovery; poison scopes remain separate operation facts. Computed keys never contribute child locations. A recorded owner may precede a dynamic native suffix. Independently, every original value on a mutable-resource route must be directly accessible: any Promise or thenable stops discovery, including synchronous delivery. Registration never substitutes its imported outcome or resumes after delivery. See [compiler construction](integration.md#compiler-construction-of-the-mutation-access-tree).

Prefix-wide mutation ordering is necessary while a key can select any descendant. In `P[i][k].x = 2`, unresolved i protects P. Once i selects a, unresolved k protects P.a and P.b can proceed. If k selects registered api, the forbidden crossing poisons the P.a.api placement under the default scope, leaving P.b healthy. A failed i instead poisons P before child selection. An explicit broader scope retains its own protection and validation. After successful target selection and establishment of ordinary target protection, a pending method or independent result must not keep unrelated siblings blocked.

## Operation lifetime

Promise-valued path work uses the owning operation's common lifetime. A consuming path component reuses its containing operation's owner. Standalone lookup, mutation, and repair already obtain their `OperationOwner` through `PathOperation`; reuse that provision point without another wrapper or optional-owner branches in walkers. Every pending segment continuation, external predecessor wait, and other asynchronous registration goes through the common guarded helpers. Only returned pending work triggers pending owner state, and prefix protection requires unfinished path selection; an independent result after target handoff cannot trigger it. The original input's callable `then` is not a readiness signal. This is generic operation state, not query state. Preserve the separation established by Phase 9F-B: capture semantics determine value retention, while common guarded continuations use the operation owner only for local-work lifetime. Version retention and publication never infer ownership from that owner's presence, type, or open state. A registered continuation first completes shared placement-version, refcount, and required settlement bookkeeping. If the operation has closed, it performs no later key normalization, traversal, lease or gate acquisition, external-phase work, host access, publication, or result production.

Observe every pending walker continuation at its originating layer even when a non-blocking mutation API does not return that Promise.

During normal or language-Error completion, publication required to finish an observation, gated mutation, or repair happens before that operation closes. Ordinary owner closure inside a live execution does not cancel an installed gate, release an external phase early, or replace their completion rules. Fatal execution failure adds no gate or phase transition: a resumed continuation sees the failed execution first and simply returns before settlement, publication, or host access. A never-resumed gate or phase may remain pending; fatal commit independently rejects every currently pending operation result through its registered outward rejection action. A standalone observation closes when its result or language-Error outcome is determined. A pending mutation normally closes only after its gate publishes success or failure; its immediate non-blocking API return is not completion and therefore needs no outward registration. A pending repair normally closes after its required managed recovery and metadata transition publish repair success or failure. When path resolution is one component of invocation, export, or an Error query, only that larger owner determines the outcome and the path creates no independent lifetime.

`hasError` and `getErrors` reuse their query owner, path export reuses its operation owner and separate output lifetime, and `run` reuses its invocation owner. Entry reference capture keeps its existing callback, managed-publication, and external-coverage lifetimes; each contained command owns its own local work. Entry coverage does not merge those command owners or make callback return prove publication. `repairPath`, standalone lookup, and ordinary mutation use the existing `PathOperation` provision above. Their completion, Error, cleanup, and ready-path behavior stays unchanged.

## External state

Actual access to mutable external state requires static registered selection and native ordering. Canonical metadata-only query and repair use ordered versions and allow computed selection. Observation-only external data supports dynamic paths without fixed-namespace protection or mutable-resource locking.

For native access, a computed key cannot select or cross a registered mutable location, even if the key is ready. Fail with ExternalLocationConflict before native reflection, capability exposure, or reservation of the dynamically selected candidate. A forbidden native observation uses immutable static-prefix authority and checks only captured own poison after required pending publications, then returns its local failure; unselected child poison and work do not contribute. A mutation with a statically selected external owner keeps tree poison at that owner, preserving its managed binding. Without such an owner, apply ordinary managed path failure at the reached placement holding the forbidden identity, or an already-selected broader mutation scope. Preserve its baseline for ordinary repair without modifying the host identity or its registration. Off-path aliases fail at their local placement, leaving the canonical location intact. Canonical metadata-only selection is permitted through computed keys. Invalid repair selection preserves all prior state; off-path aliases cannot clear canonical metadata. Earlier blocking prefix poison propagates unchanged. Repair at the selected target follows the [structural/value boundary](runtime-evolution-plan.md#failed-repair-during-the-ready-path-cutover): value-revealed authority failure after restoration is new call poison, not a reason to retain the old guard. The local-failure policy is independent of readiness and removes the static managed fallback; it grants no dynamic native authority.

Dynamic paths that select ordinary managed or observation-only external data remain supported. Do not reject them just because another child of the same prefix is mutable. Their ordinary managed prefix lease/gate preserves value ordering; contextual metadata queries and entry also retain the explicit coverage in the table above. No speculative external selection, candidate-child traversal, or global candidate wait is needed.

Unauthorized mutation of an unregistered external object uses the equivalent static path's ordinary failure scope after healthy key selection. For default assignment `P[i].ext.x = 2` with i resolving to a, poison the reached P.a.ext placement; an explicit broader scope at P.a instead owns that failure in all delivery modes. Other properties remain usable, and native ext storage is unchanged. Poison in i before selecting any child still poisons P under ordinary failed-key rules. Registered-route rejection follows the same failure-scope rule while retaining its source-static authority restriction. Both computed-path corrections and Promise-key support remain Phase 6 implementation work.

Once a static path selects a mutable external boundary for potential host access, reserve its required native coverage before waiting for dynamic suffix keys. Capture managed namespace and metadata views at issuance without awaiting native predecessors first. A known forbidden observation uses only captured prefix metadata; if an initially unknown suffix later proves forbidden, finish its required prefix-metadata consumption and complete the unused read reservation immediately. Mutation/exclusive completion still retains predecessors; early read completion permits no later live-state access. For registered api and api.db, a computed db still forbids host access and ordinary invalid mutation poisons the statically selected api owner. The same canonical path is valid for metadata-only query or repair. Before further live native access after suspension, recheck current membership for every retained external identity crossed without its canonical node, including roots and intermediates as well as the receiver. Do not replay getters or attach spent native-prefix dependencies to an already captured managed receiver. Canonical bindings are immutable; historical metadata cannot grant off-path authority.

Promise-valued operation-input keys are different from stored native property values. After crossing an external boundary, intermediate stored values, method receivers, and selected callables must be ready; do not await a stored Promise to continue the suffix. A final lookup value or direct call result may be consumed for availability. Final assignment/deletion does not read or consume the old target.

Prefix protection composes with the selected mutation scope. A coarser prefix gate can remain the publication vehicle, but it does not broaden the Error location after scope selection. Independent result readiness extends neither completed path protection nor receiver publication. Read/export/query capture finishes before source protection ends; repair retains its selected transition through publication.

External entry requires a static registered scope; compiler native-property selection uses the deepest enclosing registered node. Managed/mixed targets remain unchanged and use ordinary managed path protection plus external subtree reservation where needed. Covered entry views keep contained work ahead of later outside waiters. Managed entry still supports Promise-valued keys where they do not select registered resources.

A requested entry path may contain a dynamic suffix below an available managed anchor containing registered descendants. Establish that anchor's external coverage during issuance, before its managed gate can suspend later path capture. Retain the suffix on the private reference without consuming it; key delivery neither replaces the anchor nor narrows its coverage. A no-op callback may finish without subscribing to the key. Actual contained commands resolve the suffix at their own positions and preserve its dynamic provenance. They may query or repair canonical registered metadata through computed keys, but cannot use those keys for native access. Those consuming commands retain their ordinary path handoff; the enclosing entry retains its fixed coverage and separate managed/external completion rules. Test later static native access under the anchor, readonly and mutable entries, and nested entry without provisional reservations or late static-authority promotion. Work outside that fixed coverage remains independent.

Repair selects its canonical metadata subtree or managed guard through the common key protocol. Validate and preflight before publishing managed restoration and an empty external metadata subtree together. The reset is unconditional: do not query or wait for selected-subtree poison outcomes that it overwrites. A selected reset covering an unresolved subtree publication replaces it without waiting for that publication or its pending key; it chains only where it needs predecessor state to reach or restore its own target. Earlier captures keep their versions and native reservations keep actual host conflicts ordered. The repair's own unresolved keys, strict-ancestor own poison and required managed publication still determine its completion/error result. Failed selection or supported publication leaves state unchanged, including healthy external owners. Strict-ancestor own poison blocks selection; derived summaries do not block child repair. Canonical repair changes no registration. A rejected context import remains ordinary Error data without a recovery baseline; repair cannot make it a valid context. Repair never erases ordinary managed Error data without a baseline or changes host state. Repair-and-call preflights only the intended structural route, mutation scope and readonly capability, then composes repair and the ordinary call path under its original ordered ownership. Method-name checks (including constructor and unsupported Array names), category/dispatch, arguments and member resolution remain after committed repair; their new call failure does not restore cleared poison. Repair failure returns its causal Error and suppresses invocation. Preserve ordering from committed repair into ordinary invocation and live authority checks; neither unconditional API pairs nor deferred call issuance may discard the repair failure or lose that ordering position.

## Scope

Extend the existing observation and mutation walkers through their shared segment transitions rather than adding operation-specific paths. Reuse the existing read-lease counter, COW predicate, transition-gate placement, Promise versions, and publication transitions. Share lower-level transitions with `enter` where they are identical, but do not merge the observation and mutation walkers, route ordinary path operations through `enter`, create temporary Chains, or add another queue or path scheduler. Ready paths retain their current synchronous behavior.
